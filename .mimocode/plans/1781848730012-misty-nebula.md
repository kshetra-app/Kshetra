# Kshetra - 360-Degree Project Review & Improvement Plan

**Date:** 2026-06-19
**Scope:** Full-stack codebase analysis (Mobile + API + Shared + Data)

---

## Executive Summary

Kshetra is a well-architected political technology platform with solid foundations: Turborepo monorepo, strict TypeScript, comprehensive data coverage (36 states), and 13-language i18n. The codebase demonstrates strong engineering discipline in API design, offline-first patterns, and security awareness. However, several areas need attention before production readiness.

**Overall Health: 7/10**

## Critical Issues (Fix Before Production)

### C1: No Authentication Middleware on API
- **Impact:** All API endpoints (including AI chat) are publicly accessible
- **Evidence:** `apps/api/src/server.ts` has no auth plugin; OpenAPI spec references "Phase-2B" for Supabase JWT
- **Action:** Implement Supabase JWT verification middleware in Fastify before any public deployment

### C2: API Key Exposure in AI Status Endpoint
- **File:** `apps/api/src/routes/ai.ts:103`
- **Issue:** `configured: !!process.env.OPENAI_API_KEY` leaks whether API key exists
- **Action:** Remove this check or move to internal-only endpoint

### C3: Groq API Key Bundled in Client
- **Issue:** `EXPO_PUBLIC_GROQ_API_KEY` is prefixed with `EXPO_PUBLIC_`, meaning it's bundled into the client bundle
- **Action:** Evaluate if Groq calls should go through the backend API instead

### C4: CSP Disabled Entirely
- **File:** `apps/api/src/server.ts` - `contentSecurityPolicy: false`
- **Action:** Configure proper CSP directives for Expo compatibility rather than disabling

## High-Priority Improvements

### H1: God File - `supabaseDataService.ts` (1,165 lines)
- **Current:** Single file handles every Supabase operation for the entire app
- **Action:** Split into domain-specific files:
  - `services/issues.ts`
  - `services/feed.ts`
  - `services/promises.ts`
  - `services/affidavits.ts`
  - `services/profile.ts`
  - `services/search.ts`
  - `services/moderation.ts`

### H2: Mobile Test Coverage Gap
- **Current:** Only 3 test files for 80+ components, 68 lib files, 25 stores
- **Action:** Add tests for:
  - Zustand stores (at least top 10 by complexity)
  - Critical data services
  - Key components (IssueCard, PostCard, ConstituencyResultCard)

### H3: Empty Catch Blocks (54 instances)
- **Current:** Silent error swallowing makes debugging nearly impossible
- **Action:** Add at minimum `console.debug()` or `captureException()` to all bare catches
- **Priority files:** `stores/auth.ts:58`, `lib/supabaseDataService.ts` (multiple)

### H4: Oversized Components (>800 lines)
| Component | Lines | Action |
|-----------|-------|--------|
| `ShortsPlayerModal.tsx` | 858 | Extract controls, player logic, comments into sub-components |
| `ContentGateActions.tsx` | 623 | Split paywall/preview/CTA into separate components |
| `CompareSheet.tsx` | 591 | Extract comparison logic, table renderer |
| `KYCVerificationSheet.tsx` | 586 | Split form steps into sub-components |
| `UploadShortModal.tsx` | 587 | Separate upload, preview, metadata steps |

### H5: ESLint Not Blocking in CI
- **Current:** `continue-on-error: true` on ESLint and mobile typecheck
- **Action:** Make blocking once `any` debt is reduced to acceptable levels

## Medium-Priority Improvements

### M1: Code Duplication in Data Layer
- `stateDataAdapter.ts` (438 lines) and `stateDataDispatcher.ts` (587 lines) overlap significantly
- **Action:** Consolidate into single adapter with clear responsibilities

### M2: Route Pattern Duplication
- `apps/api/src/routes/constituencies.ts` repeats `if (stateCode.toUpperCase() !== 'TS')` guard
- **Action:** Extract to middleware or shared guard function

### M3: Relative Path Imports
- `apps/api/src/services/ai.ts` uses `../../../../data/seed/telangana-constituencies`
- **Action:** Convert to workspace package imports

### M4: Type Safety Debt (96 `any` in mobile/lib)
- **Top offenders:** `maplibreCompat.tsx` (14+), `supabaseDataService.ts` (15+)
- **Action:** Create proper types for MapLibre compatibility layer; type Supabase return values

### M5: Per-Package Lint Scripts
- `apps/api` and `packages/shared` have `"lint": "echo lint"`
- **Action:** Wire up proper ESLint execution at package level

### M6: Stub Routes Without Documentation
- `campaign.ts`, `civic.ts`, `journalist.ts`, `politician.ts` return hardcoded data
- **Action:** Add JSDoc noting these are placeholder implementations

## Low-Priority Improvements

### L1: Mobile `lib/` Directory Organization
- 68 files in flat structure mixing types, adapters, services, utilities, hooks
- **Action:** Create subdirectories: `lib/services/`, `lib/types/`, `lib/hooks/`, `lib/utils/`

### L2: Store Size Reduction
- `civic.ts` (982 lines), `affidavits.ts` (914 lines), `feed.ts` (740 lines)
- **Action:** Extract complex actions into separate service files, keep stores thin

### L3: Test Coverage Thresholds for Seed Data
- `data/seed` tests exist but have no coverage thresholds
- **Action:** Add minimum thresholds

### L4: `continue-on-error` on Security Scans
- Semgrep, npm audit, OSV findings are surfaced but not enforced
- **Action:** Make blocking for critical/high severity findings
