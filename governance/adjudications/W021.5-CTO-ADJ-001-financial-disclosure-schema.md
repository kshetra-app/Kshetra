## 1. Question adjudicated

Whether the repository's proposed normalized affidavit disclosure schema is an acceptable permanent design correction for the legacy behavior that converted missing/unfiled asset or liability disclosures into false zero-valued financial claims.

## 3. Technical ruling

The schema design is approved because the reviewed migration specifies nullable numeric disclosure fields without synthetic zero defaults, separates self/spouse/dependent and movable/immovable categories, separates assets from liabilities, and defines non-negative checks and canonical person/candidacy links.

The defect's repository-design disposition is therefore:

`RESOLVED_IN_REPOSITORY_DESIGN — CTO TECHNICAL ADJUDICATION GRANTED; STAGING VERIFICATION PENDING`

This ruling supersedes the previous requirement for another CTO design decision on this exact schema question. It does not certify any candidate's actual disclosure data and does not claim that Migration 068 has been applied to staging.

## 4. Mandatory conditions before database acceptance

1. Rerun the financial remediation tests at the exact resumption branch head and preserve stdout, stderr, exit code and SHA-256 manifest.
2. Inspect Migration 068 in full for FK target consistency with the actual canonical schema, RLS policies, grants and public read semantics. Correct any mismatch in a new forward migration, not by rewriting history.
3. Deliver an owner-executable staging SQL package with explicit target-project preflight, transaction boundaries, postflight assertions, and rollback/recovery notes.

5. Verify catalog facts: columns remain nullable; no zero defaults exist for missing disclosure amounts; non-negative constraints and intended FKs exist; RLS is enabled and policies are correct; no production access occurred.
6. Verify serialization and UI behavior: SQL NULL / absent affidavit must render as “Not Disclosed” (or the approved localized equivalent), never ₹0; explicitly disclosed ₹0 remains distinguishable from undisclosed.
7. Keep record-level source provenance and affidavit effective/filing dates. Do not mark data OFFICIAL without a traceable source artifact.
