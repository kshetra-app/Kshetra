## 1. Executive Summary & Defect History

Defect `DQ-W021.5-B2.2E-001` was originally identified during the W021.5-B2.2-E candidate affidavits and demographics audit. The defect stemmed from legacy Supabase schema `supabase/migrations/008_election_affidavits.sql`, which modeled candidate movable and immovable financial assets and liabilities using:
```sql
total_assets BIGINT NOT NULL DEFAULT 0,
total_liabilities BIGINT NOT NULL DEFAULT 0
```
This legacy DDL had three fatal data-truth consequences:
1. **Synthetic ₹0 Attribution:** Candidates who filed Form 26 affidavits with unstated, contested, or exempt financial disclosures were automatically recorded as possessing ₹0 assets and ₹0 liabilities.
2. **False Electoral Cleanliness Claims:** Downstream consumers (e.g. mobile `FinancialBreakdownCard`, `CrorepatiRatio`, and `ConstituencyIntegrity`) interpreted `total_assets: 0` as an affirmative declaration of zero wealth, misleading voters.
3. **Cross-Entity Collapse:** Assets owned individually by the candidate, spouse, and dependents were forcibly aggregated into single totals, obscuring legal ownership structures.

## 2. Root-Cause Analysis

| Dimension | Legacy Flaw (Migration 008) | Remediated Standard (DEC-134 / Migration 068) |
|---|---|---|
| **Null Semantics** | `NOT NULL DEFAULT 0` coerced missing data to ₹0 | `BIGINT NULL CHECK (val >= 0)` preserves genuine null |
| **Asset Granularity** | Single aggregate `total_assets` | Disaggregated `self_movable`, `spouse_movable`, `dependent_movable`, `self_immovable`, etc. |
| **Liabilities Distinction** | Conflated with assets | Independent `self_liabilities`, `spouse_liabilities`, `dependent_liabilities` |
| **Mobile Serialization** | `formatINR(0) => '₹0'` displayed for unstated assets | `formatINR(null) => 'Not Disclosed'` fail-closed rendering |
| **Mathematical Sum Checks** | None | Enforced check constraints: `total = self + spouse + dependents` |

## 3. The DEC-134 Authoritative 6-Rule Schema Standard

To definitively resolve `DQ-W021.5-B2.2E-001`, CTO Directive 134 formulated the 6-rule standard:
1. **Strict Nullability:** Asset and liability fields must be defined as `BIGINT NULL CHECK (val >= 0)`. Zero synthetic defaults are permitted.
2. **Disaggregation of Asset Classes:** Movable and immovable assets must be stored in distinct columns.
3. **ECI Form 26 Sworn Disclosures:** Candidate, spouse, and dependent assets must be separately tracked without cross-entity averaging.
4. **Distinct Gross vs Net Liabilities:** Liabilities must be tracked separately from gross assets with non-collapsing nulls.
5. **Fail-Closed Serialization:** Mobile and API presentation layers must render explicit nulls (`formatINR(null) => 'Not Disclosed'`) preventing false ₹0 displays.
6. **Canonical Migration 068 DDL:** Implemented in `supabase/migrations/068_affidavit_disclosures.sql` to formalize the standard in the repository.
