## 3. Workstream B — DM Unread-Count Error Behavior Remediation

### Defect Identified
In Directive 116, non-production fallbacks were added to `GET /api/v1/dm/unread-count` in `apps/api/src/routes/dm.ts`:
```typescript
if (process.env.NODE_ENV !== 'production') {
  return reply.send({ success: true, count: 0 });
}
```
This masked database query errors during testing, converted database timeouts into fake zero unread counts, and introduced 14+ second network timeout stalls during test runs.

### Remediation Executed
1. **Removed Non-Production Fallback:** Deleted the bypass blocks from `convError`, `countError`, and the `catch` block in `apps/api/src/routes/dm.ts`.
2. **Fail-Closed Contract Enforced:** Any database query error strictly throws and returns `500 DATABASE_ERROR` fail-closed in all environments:
   ```json
   {
     "error": "Internal Server Error",
     "message": "Failed to retrieve unread count",
     "statusCode": 500,
     "code": "DATABASE_ERROR"
   }
   ```
3. **Dedicated 5-Case Regression Suite Authored:** Created `apps/api/src/__tests__/dm-unread-count.test.ts` verifying all 5 contract cases:
   - **Case 1 (Zero Unread Messages):** `200 OK`, `{ success: true, count: 0 }` (PASS)
   - **Case 2 (Positive Unread Count):** `200 OK`, `{ success: true, count: 5 }` (PASS)
   - **Case 3 (Conversation Lookup Failure):** `500 DATABASE_ERROR`, count undefined (PASS)
   - **Case 4 (Message Count Query Failure):** `500 DATABASE_ERROR`, count undefined (PASS)
   - **Case 5 (Unconfigured Database):** `503 DATABASE_UNAVAILABLE`, count undefined (PASS)
4. **Deterministic Mocking:** Spied on `supabase.from` in `dm-rate-limits.test.ts`, reducing test execution time from 14,091 ms to 36 ms.
