### 5.3 Generated-Column-Safe Asset Representation Methods

Because `total_assets` is defined as `GENERATED ALWAYS AS (...) STORED`, direct SQL update raises PostgreSQL error `42601`. Three implementation methods are available:

#### Method A: DDL Normalization in Migration 067 (Architecturally Cleanest)
- **Syntax:**
  ```sql
  ALTER TABLE public.candidate_affidavits ALTER COLUMN total_assets DROP EXPRESSION IF EXISTS;
  ```
- **Evaluation:** Converts `total_assets` from a generated expression into a standard `BIGINT` column in PostgreSQL 12+ without dropping existing data. Allows direct, high-performance batch updates for both the 4,340 positive assets and the 72 `NULL` assets. Truthfully models the reality that 26 states only possess total asset disclosures without component breakdowns.

#### Method B: Component Attribution (Zero DDL Change)
- **Syntax:**
  - For 6 component states (990 positive): Update `self_movable_assets` and `self_immovable_assets` from seed.
  - For 26 total-only states (3,350 positive): Attribute total assets to `self_movable_assets = total_assets`, leaving other components `0`. Generated column computes `total_assets + 0 + 0 + 0 = total_assets`.
  - For 72 missing assets: Set all 4 component columns to `NULL`, evaluating `total_assets = NULL`.
- **Evaluation:** Avoids DDL changes, but artificially classifies 100% of candidate wealth as "movable" in 26 states.

#### Method C: Two-Phase Decoupling (Governance-Safe)
- **Phase 1 (Migration 067):** Remediate exclusively the 965 missing disclosures (Category 1) by setting component columns to `NULL` for the 72 asset cases, and `total_liabilities = NULL` for the 893 liability cases. Formally closes defect `DQ-W021.5-B2.2E-001`.
- **Phase 2 (Migration 068):** Author a dedicated asset restoration migration under a new CTO directive with DDL normalization or enriched seed components.
