## 5. Authentication & Error Truthfulness Hardening

Directive 139 required complete closure of security gaps in Fastify API authentication and Class B write route handling.

### 5.1 Architecture Overhaul in `apps/api/src/lib/userAuth.ts`
1. **Elimination of Synthetic Token Fallback:**
   - Previous behavior: When Supabase was unconfigured, arbitrary tokens starting with `user-` or `test-` were accepted as valid authenticated users.
   - New behavior: In production or standard runtime, unconfigured Supabase Auth fails closed with HTTP 503 `AUTH_PROVIDER_UNAVAILABLE`.
2. **Production-Guarded Isolated Test Validator:**
   - Introduced `setTestTokenValidator(validator: TestTokenValidator | null)`.
   - Guarded by an explicit fail-closed runtime check:
     ```typescript
     if (process.env.NODE_ENV === 'production' && validator !== null) {
       throw new Error('SECURITY VIOLATION: Test token validator cannot be registered in production runtime.');
     }
     ```
3. **Elimination of Header-Based Role & User ID Spoofing:**
   - `x-user-role` and `x-user-id` headers are completely ignored in production identity resolution.
   - User identity and role are derived exclusively from the verified token payload.
4. **Enforced Actor Matching:**
   - `assertActingUserMatch(request, reply, targetUserId)` rejects any mismatch between the authenticated user and the requested resource owner with HTTP 403 `FORBIDDEN`.

### 5.2 Fail-Closed Database Unavailability across Class B Write Routes
All Class B write endpoints were updated to fail closed when `!isSupabaseConfigured` or on database connection failure, returning structured error envelopes rather than fabricated responses:
