## 1. Executive Summary & Objective

CTO Directive 120 required converting the existing W021.5 foundation into a demonstrably more complete, internally consistent, tested, and releasable implementation without weakening test thresholds, falsifying capability declarations, or violating the non-self-acceptance mandate.

This implementation work package delivers:
1. **Four New Isolated Jest Unit Test Suites** addressing previously uncovered core services and routes that skipped in headless CI:
   - `apps/api/src/__tests__/political-entity-service-unit.test.ts` (34 passing tests)
   - `apps/api/src/__tests__/election-service-unit.test.ts` (20 passing tests)
   - `apps/api/src/__tests__/spatial-analytics-unit.test.ts` (25 passing tests)
   - `apps/api/src/__tests__/spatial-runtime-unit.test.ts` (17 passing tests)
2. **Expansion of Delimitation Query Unit Tests**:
   - `apps/api/src/__tests__/delimitation-query-unit.test.ts` expanded from 20 to 35 tests, testing all 5 W014 `resolveRegime` modes (`current`, `as_of`, `explicit`, `future_anticipated`, `scenario`), timeline events, and delimitation status DTOs.

   - In `apps/api/src/routes/ai.ts`, replaced Telangana-hardcoded limit `TS_MAX_AC = 119` with national bounds `MIN_AC_NO = 1; MAX_AC_NO = 500;`.
   - Added optional `stateCode` parameter across conversational AI, quick constituency analysis, and smartSearch.
   - In `apps/api/src/services/ai.ts`, wired constituency context and index generation into `stateData.ts` multi-state getters (`getConstituency`, `getConstituencyElectionData`, `getStateInfo`, `getConstituencies`).
   - Added automated multi-state test coverage in `apps/api/src/__tests__/ai.test.ts` (8/8 passing).
4. **National Geographic Capability Truth Alignment in Mobile Consumer**:
   - In `apps/mobile/lib/stateRegistry.ts`, replaced false declarations of `hasGeoJSON: true` for 26 non-TS states/UTs with `hasGeoJSON: false`. Strictly Telangana (`TS`) remains `hasGeoJSON: true`, perfectly aligning the mobile app with the API service `apps/api/src/services/stateData.ts`.
   - Verified that all 23 mobile test suites run completely clean (326/326 passing tests).
5. **CI Workflow & Jest Teardown Optimization**:
   - Added `forceExit: true` to `apps/api/jest.config.js`.
   - Removed redundant `--forceExit` flag from `.github/workflows/ci.yml` line 82, as mandated by Directive 119.
6. **Fixture Credentials & Fail-Closed Behavior Verification**:
   - Verified `apps/api/src/__tests__/fixture-credentials-fail-closed.test.ts` (8/8 passing tests), proving that test fixtures in `jest.config.js` and `ci.yml` cannot cause an unavailable integration database to be treated as live, and proving zero leakage of production or staging project IDs.

## 3. Geographic Capability Truth Correction

### 3.1 Mobile State Registry Alignment
Prior to this directive, `apps/mobile/lib/stateRegistry.ts` declared `hasGeoJSON: true` for 27 states/UTs, creating a false capability assertion for 26 jurisdictions where no RFC 7946 GeoJSON boundary assets exist in the repository.

In `apps/mobile/lib/stateRegistry.ts`:
- Replaced `hasGeoJSON: true` with `hasGeoJSON: false` for all 26 non-TS jurisdictions:
  `AP`, `KA`, `MH`, `RJ`, `GJ`, `DL`, `OD`, `JH`, `BR`, `PB`, `HR`, `UK`, `CG`, `MP`, `AS`, `GA`, `HP`, `JK`, `MN`, `ML`, `MZ`, `NL`, `TR`, `SK`, `AR`, `PY`.
- Preserved strictly `TS: hasGeoJSON: true`, backed by `data/geo/telangana-assembly.geojson`.
- Synchronized client-side registry with API capability contract in `apps/api/src/services/stateData.ts`.
- Ran full mobile test suite: **23 test suites passed, 326 tests passed**.

## 4. Workstream 3: AI Multi-State Generalization

### 4.1 Route Changes (`apps/api/src/routes/ai.ts`)
- Replaced:
  ```ts
  const TS_MIN_AC = 1;
  const TS_MAX_AC = 119;
  ```
  with:
  ```ts
  const MIN_AC_NO = 1;
  const MAX_AC_NO = 500;
  ```
- Added optional `stateCode: z.string().trim().length(2).optional()` to:
  - `chatBodySchema`
  - `constituencyQuerySchema`
  - `smartSearchBodySchema`
- Updated route handlers:
  - `POST /api/v1/ai/chat`: passes `stateCode` to `chatWithAI`
  - `GET /api/v1/ai/analyze/constituency/:acNo`: accepts `?stateCode=XX` (defaults to `'TS'`), returns `{ acNo, stateCode, analysis }`
  - `POST /api/v1/ai/smart-search`: accepts `stateCode` and passes it to `smartSearch`

### 4.2 Service Changes (`apps/api/src/services/ai.ts`)
- Imported `getConstituency`, `getConstituencyElectionData`, `getStateInfo`, `getConstituencies` from `./stateData`.
- Generalized `buildConstituencyContext(acNo?: number, stateCode = 'TS')`:
  - If `stateCode === 'TS'`: retains rich baseline with historical results, demographics, MLA profiles, and political timeline events.
  - If `stateCode !== 'TS'`: dynamically retrieves canonical brief and certified recent election records via `stateData` services.
- Generalized `smartSearch(query: string, stateCode = 'TS')`:
  - Dynamically builds prompt index using the specified state's constituency roster and MLA data.
- Added tests in `apps/api/src/__tests__/ai.test.ts` verifying non-TS AC numbers beyond 119 and multi-state searches.
