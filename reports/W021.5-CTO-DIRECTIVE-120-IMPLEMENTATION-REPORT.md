### 3.1 Key Architectural & Hardening Details
1. **LMX Routes (`src/routes/lmx.ts`):**
   - Covered all moderation decision outcomes (`cut`, `allow`, `mute`, `escalate`).
   - Hardened AJV schema compliance: strict enforcement of required `department_id`, `alert_type`, and `message` fields.
   - Tested custom stream filtering parameters (`category=all`, `status=all`, `status=ended`, `state=TS`) and custom `buffer_state` transitions (`buffered`, `cleared`, `bypassed`, `rejected`).
2. **Constituencies Routes (`src/routes/constituencies.ts`):**
   - Tested `TS-AC-X` id parsing branch, lowercase state code validation rejection (400 per `^[A-Z]{2}$` regex), and missing election data coercion defaults.
   - Verified multi-field text search (`q` covering district, MLA name, ID, and AC number).
   - Validated single and pair margin filters (`minMargin`, `maxMargin`), margin cascade fallbacks (`margin2025` through historical `margin`), and sorting modes (`name`, `margin_asc`, `margin_desc`, default `acNo`).
   - Covered MLA profile boundaries (`< 1` or `> 119`) and point location spatial fallbacks.
3. **Canonical Election Service (`src/services/electionService.ts`):**
   - Verified limit/offset clamping (`limit > 50`, `limit < 1`, `offset < 0`) and null query handling.
   - Covered contest and ballot choice query error branches.
   - Tested sparse mapper records (null electors, null turnout, unestablished contests) and candidate fallbacks (runner-up missing, candidate lacks person record).
4. **State Data Service (`src/services/stateData.ts`):**
   - In-memory seed testing via `getTSRawSeeds()` to exercise internal branch logic without module-seam mocking issues.
   - Covered Delhi 2025 (`DL`) `winner2025` results, explicit `electionYear` in raw records, and election types (`BYPOLL` vs. `GENERAL`).
   - Verified vote count coercion to null for non-numeric fields and margin percent guards (`winnerVotes <= 0`, `margin < 0`).
5. **Spatial Runtime Service (`src/services/spatialRuntimeService.ts`):**
   - Covered `encodeValue` property encoding across numbers, strings, nulls, and undefined values.
   - Tested MultiPolygon geometry and degenerate polygon ring handling (< 3 coordinates, closed rings).
   - Verified regime branches: unsupported regime exception (`INVALID_REGIME`), historical regime with `asOf`, and version regime with `versionId`.
   - Covered PostGIS `st_intersects` RPC error paths, `bypassAdapter: true` direct execution, and coordinate boundary validations.
6. **Campaign Routes (`src/routes/campaign.ts`):**
   - Covered payment order creation failures and error handling.
   - Verified fail-closed cryptographic signature verification: `PROVIDER_CONFIG_ERROR` on missing secret (500), `INVALID_SIGNATURE` on invalid HMAC (400), and generic verification exception handling (400).
   - Tested cross-wallet recharge verification rejection (403) and effective politician identity binding.
   - Validated offline in-memory order resolution, booth 404 / volunteer 503 fallback paths, and offline idempotent recharge replay.
