## 7. DETERMINATION OF AUTHORITATIVE EXPECTED COUNT

### 7.1 Why the Manifest Contains 11,334
The manifest was constructed by concatenating candidate extractions across:
1. `data/seed/*-mla-profiles.ts` (31 files)
2. `data/seed/mp-profiles.ts` (1 file)
3. `data/seed/*-historical-results.ts` (8 files)
4. `data/seed/*-constituencies.ts` (31 files)

The manifest generator used an in-memory key:
```javascript
const candKey = `${normName}::${raw.electionYear}::${raw.electionType}::${raw.stateCode}::${constId}`;
```
Because of slight differences in raw formatting in seed files (e.g. `O. S. Ambika` in the MLA profile vs `O S Ambika` in the constituency file), `normName` produced `o  s  ambika` vs `o s ambika`, failing to deduplicate at the string level. Both occurrences entered `w021_5b2_b2_2d_candidacy_manifest.json`, giving a total of **11,334 raw occurrences**.

### 7.2 Why the Database Schema Contains 11,298
When these occurrences were mapped to canonical entities, both occurrences resolved to the **same canonical person**.
The authoritative schema defines:
```sql
CONSTRAINT uq_candidacies UNIQUE (person_id, election_year, election_type, constituency_id);
```
Under Indian electoral law and relational modeling:
- A candidate cannot hold multiple distinct candidacies for the same constituency election in the same year.
- Therefore, there are only **11,298 real electoral candidacies**.
- Inserting the second occurrence would create duplicate rows for the identical contest, corrupting aggregate candidate statistics and vote tallies.

### 7.3 Architectural Deduplication Rule
```text
IF candidacy A and candidacy B have identical (person_id, election_year, election_type, constituency_id):
  RETAIN candidacy A (from *-mla-profiles.ts)
```
