## 2. MATERIAL CONTRADICTION REQUIRING RESOLUTION

### 2.1 The Contradiction Identified
The previous readiness dossier presented an irreconcilable contradiction:
1. It stated: *"constituency_id is an unconstrained text identifier"*.
2. Concurrently, it asserted: *"constituency dependency closure: 0 missing dependencies"*, *"constituency-type validation"*, and *"canonical constituency relationships verified"*.

### 2.2 Forensic Analysis of the Contradiction
A column cannot simultaneously be an *unconstrained text field holding raw source stubs* and claim *canonical relational dependency closure* against the database constituency registry without an explicit, verifiable resolution contract.
- The live database table `public.candidacies` contains **NO foreign key constraint** on `constituency_id`.
- The values populated into `constituency_id` across the 11,334 raw tuples are **not canonical database primary keys**:
  - Assembly candidacies contain bare, un-prefixed codes: `'AC-1'`, `'AC-2'`, ..., `'AC-403'`, plus `'STATE'`.
  - Parliamentary candidacies contain raw text slugs: `'adilabad_(st)'`, `'agra_(sc)'`, `'ahmedabad_east'`.
- The canonical staging constituency registry (`public.constituencies` and `public.parliamentary_constituencies`) defines entirely different keys:
  - `public.constituencies.id` uses state-prefixed codes (e.g. `'TS-AC-1'`, `'AP-AC-1'`, `'JK-AC-15'`).
  - `public.constituencies.canonical_code` uses zero-padded codes (e.g. `'TS-AC-001'`, `'AP-AC-001'`).
  - `public.parliamentary_constituencies.id` uses UUIDs (e.g. `'d05821b1-6a21-4283-85b6-e918b3066a7b'`).
  - `public.parliamentary_constituencies.code` uses state-prefixed codes (e.g. `'TS-PC-01'`).
- In isolation, **404 out of 404** assembly identifiers and **540 out of 540** parliamentary identifiers fail direct primary-key and code matching against the staging constituency tables.
- Without linking through `canonical_persons.state_code`, bare `'AC-1'` is ambiguous across **31 separate states/UTs** in India.

This constitutes a material schema contract defect that requires formal CTO review and architectural disposition before any staging execution may be authorized.

## 4. CONSTITUENCY IDENTITY & RESOLUTION MECHANISM

### 4.1 Exact Type and Semantic Meaning of `constituency_id`
- **PostgreSQL Data Type:** `text`, `NOT NULL`.
- **Semantic Role:** It functions as an **unconstrained textual natural-key component**. It was designed as unconstrained `text` because `public.candidacies` stores contests across multiple electoral jurisdictions (assembly, parliamentary, local body, panchayat).

### 4.2 Proof of Absence of Foreign Key
- Information schema query on `table_constraints` joined with `key_column_usage`:
  $$\text{Foreign Keys on } \texttt{public.candidacies.constituency_id} = 0$$
- In relational database design, PostgreSQL cannot place a single foreign key on `constituency_id` pointing to both `public.constituencies` (Assembly) and `public.parliamentary_constituencies` (Lok Sabha).

### 4.3 Nature of `constituency_type`
- **Actual Column:** Yes, `constituency_type` is an actual physical column (ordinal position 5, `text`, `NOT NULL`).
- **Database Enforcement:** Enforced by check constraint `candidacies_constituency_type_check` (`parliamentary`, `assembly`, `local_body_ward`, `panchayat`).
- **Function:** Disambiguates whether the contest occurred at the national parliamentary tier or state assembly tier.

### 4.4 The Intended Canonical-Resolution Mechanism vs Actual Data
In the staging database architecture:
- **Assembly Constituencies** are canonicalized in table `public.constituencies`:
  - Primary Key `id`: State-prefixed text (e.g. `'AP-AC-1'`, `'TS-AC-1'`, `'JK-AC-15'`).
  - Canonical Code: Zero-padded string (e.g. `'AP-AC-001'`, `'TS-AC-001'`).
  - Columns: `ac_no integer`, `state_code text`, `name text`.
- **Parliamentary Constituencies** are canonicalized in table `public.parliamentary_constituencies`:
  - Primary Key `id`: Immutable UUID (e.g. `'d05821b1-6a21-4283-85b6-e918b3066a7b'`).
  - Canonical Code: State-prefixed string (e.g. `'TS-PC-01'`).
  - Columns: `pc_number integer`, `state_code text`, `name text`.

**The Architectural Mismatch:**
The candidacy seed package populates `constituency_id` with:
- Bare assembly numbers: `'AC-1'`, `'AC-2'`, ... `'AC-403'`, and `'STATE'`.
- Raw lowercase slugs: `'adilabad_(st)'`, `'agra_(sc)'`.

Because `public.candidacies` **does not have a `state_code` column**, an assembly value of `'AC-1'` cannot be resolved to a unique row in `public.constituencies` without joining through `canonical_persons.state_code` or `elected_tenures`!
