### 2.1 The Geometry Availability Contradiction Resolved
Previously, `apps/api/src/services/stateData.ts` declared `VALIDATED_GEOJSON_STATES = new Set(['TS'])` (`hasGeoJSON: true`), which contradicted `scripts/validate_stage_b_geography.mjs` and all Stage B test suites, where `hasGeoJSON` was enforced to be `false` due to the unresolved AC 119 defect (`DEF-W021-01`).

### 2.2 6-Tier Geographic Capability Model Implementation
To prevent a single boolean from conflating file asset existence, coordinate geometry validity, 1:1 statutory seat linkage, and authoritative acceptance, a granular 6-tier capability model was introduced in `apps/api/src/services/stateData.ts`:

```typescript
export type GeographicBoundaryStatus =
  | 'UNAVAILABLE'              // No boundary file exists in canonical data/geo/
  | 'MALFORMED'                // File exists but JSON is corrupted or rings unclosed
  | 'STRUCTURALLY_VALID'       // RFC 7946 valid coordinates and rings, but unlinked or partial
  | 'CONFLICT_PENDING'         // Geometry valid, but has unresolved feature conflicts / duplicates
  | 'LINKED_PROVISIONAL'       // Linked 1:1 to canonical constituencies, but unverified statutory provenance
  | 'ACCEPTED_AUTHORITATIVE';  // Fully accepted authoritative boundary by CEO / ECI / statutory body

export interface GeographicCapability {
  hasBoundaryAsset: boolean;
  boundaryStatus: GeographicBoundaryStatus;
  isStructurallyValid: boolean;
  hasCleanConstituencyMapping: boolean;
  isAuthoritativeAccepted: boolean;
  activeDefects: string[];
  notes?: string;
}
```

### 2.3 Fail-Closed Standardization & Consumer Reconciliation
- **`VALIDATED_GEOJSON_STATES`**: Standardized to `new Set<string>([])` (strictly empty). Zero States/UTs currently possess accepted authoritative geometry without open defects or unverified provenance.
- **`hasGeoJSON`**: Evaluates fail-closed to `false` for all 31 States/UTs.
- **`hasBoundaryAsset`**: Truthfully reports `true` for Telangana and `false` for the other 30 States/UTs.
- **Consumer Updates**:
  - `apps/api/src/routes/saasV1.ts`: Surfaces `geographicCapability` in response envelope, setting `hasSpatialBoundaries: info.hasGeoJSON` (`false`), preventing downstream API clients from assuming unverified boundaries are authoritative.
  - `apps/api/src/routes/states.ts`: Response schema updated to validate `hasGeoJSON` and nested `geographicCapability` schema.

## 3. WORKSTREAM B — FORENSIC AC 119 INVESTIGATION (DEF-W021-01)

### 3.1 Forensic Evidence Breakdown
Deep inspection of `data/geo/telangana-assembly.geojson` features for AC 119 revealed:
- **Feature Index 118:** `FID: 4159`, `OBJECTID: 4184`, `AC_NO: 119`, `AC_NAME: 'Bhadrachalam (ST)'`, `DIST_NAME: 'KHAMMAM'`, `PC_NO: 16`. Coordinates: 2,139 points, BBox: [80.37–81.10 E, 17.73–18.63 N], Area: 0.1719 sq deg (Northern main body).
- **Feature Index 119:** `FID: 4160`, `OBJECTID: 4188`, `AC_NO: 119`, `AC_NAME: 'Bhadrachalam (ST)'`, `DIST_NAME: 'KHAMMAM'`, `PC_NO: 16`. Coordinates: 152 points, BBox: [80.88–80.91 E, 17.638–17.681 N], Area: 0.00071 sq deg (Southern detached revenue pocket).

### 3.2 Authoritative State GIS Verification & Root Cause Determination
Inspection of the official state GIS dataset from the Telangana Remote Sensing Applications Centre (`data/geo/candidate_authoritative/tgrac_assembly_constituencies_raw.json`) revealed that Feature Index 114 (`ASSEMBLY_N: 'Bhadrachalam (St)'`) contains **2 rings** in a single feature, with Ring 0 matching FID 4160's bounding box and Ring 1 matching FID 4159's bounding box.

**Root Cause:**
The two records are **NOT** conflicting boundary versions or duplicate rows. They are two disjoint geographic parts of a legitimate multi-part assembly constituency created by the Andhra Pradesh Reorganisation (Amendment) Act, 2014, when 7 mandals of Khammam district were transferred to Andhra Pradesh for the Polavaram irrigation project, leaving Bhadrachalam town and non-contiguous revenue villages in Telangana.
Upstream community open-source Datameet shapefile export improperly dumped this multi-part polygon as two separate `Polygon` Features instead of a single `MultiPolygon` Feature, resulting in 120 features for 119 statutory seats.

### 3.3 Rule IV-001 Governance Handling
- **Arbitrary manual deletion of FID 4160 is strictly forbidden** (it would discard legitimate Telangana territory).
- **Ad-hoc merging into a single feature in the canonical asset is strictly forbidden** without official CEO Telangana gazette confirmation.
- **Disposition:** Defect `DEF-W021-01` remains **`OPEN_AND_BLOCKED`**.
- **Safeguards Enforced:** Fail-closed capability reporting (`hasCleanConstituencyMapping = false`, `hasGeoJSON = false`, `boundaryStatus = 'CONFLICT_PENDING'`).
