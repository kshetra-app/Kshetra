### Design A: Retain the Generated Total (Component Synthesis)
- **Mechanics:** Retain `total_assets GENERATED ALWAYS AS (self_movable + self_immovable + spouse_movable + spouse_immovable) STORED`. For 26 states where only `totalAssets` is known, synthesize components (e.g. assign 100% to `self_movable_assets` and 0 to others).
- **Evaluation:**
  - *Source-Truth Fidelity:* **DEFICIENT.** Fabricates the claim that 100% of candidate assets are movable.
  - *Missing vs Zero Semantics:* Supports `NULL` (by setting all 4 components to `NULL`).
  - *Component Fidelity:* **CORRUPTIVE.** Distorts economic analytics.
  - *Recommendation:* **STRICTLY REJECTED.**

### Design B: DDL Normalization (Make Total Assets Independently Representable) — RECOMMENDED
- **Mechanics:** Execute:
  ```sql
  ALTER TABLE public.candidate_affidavits ALTER COLUMN total_assets DROP EXPRESSION IF EXISTS;
  ```
  Converts `total_assets` from a generated column to a standard nullable `BIGINT` column in PostgreSQL 12+. Existing table data is preserved in place.
- **Evaluation:**
  - *Source-Truth Fidelity:* **100% FLAWLESS.** Stores the exact authoritative manifest values for all 4,340 non-zero assets ($\sum = \text{₹10,023.48 Cr}$).
  - *Missing vs Zero Semantics:* **100% CLEAN.** Stores `NULL` for the 72 missing assets; stores `0` for the 111 genuine zeros.
  - *Component Fidelity:* **TRUTHFUL.** For the 26 total-only states, components are set to `NULL` (reflecting that breakdown was undisclosed), preventing fabricated allocations. For the 6 component states, verified components can be populated.
  - *Consumer Compatibility:* **100% PASS.** Completely transparent to all mobile and API callers.
  - *Migration & Rollback Complexity:* **LOW.** Forward is a single instant DDL statement; rollback re-adds the generation expression.
  - *Recommendation:* **RECOMMENDED ARCHITECTURAL TARGET.**

### Design C: Parallel Column Architecture (`source_total_assets`)
- **Mechanics:** Keep `total_assets` generated, but add a new column `declared_total_assets BIGINT`.
- **Evaluation:** Requires refactoring TypeScript interfaces, dispatchers, SQL views, and mobile UI components across dozens of files.
- *Recommendation:* **REJECTED** due to high blast radius and contract churn.
