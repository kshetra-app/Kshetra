## 3. Verifier Integration & Gate Mechanics (§3)

In Directive 071, `scripts/generate_adjudication_manifest.mjs` imported `parseSourceProfile()` but evaluated eligibility using internal heuristic `if/else` logic. Directive 072 eliminates all heuristic shortcuts and replaces them with direct invocation of `validateCorrectionEligibility()` from `scripts/verify_financial_remediation.mjs`:

```javascript
// Actual invocation for each proposed candidate mutation
try {
  validateCorrectionEligibility(manifestRecord, correction, fieldType, crosswalkMap, ledgerMap, REPO_ROOT);
  passesExistingOfflineVerifier = true;
  verifierRejectionReason = null;
  eligibility = 'ELIGIBLE';
  eligibilityReason = 'SOURCE_VERIFIED: Fully verified by existing offline verifier against component ledger and source coordinate.';
} catch (err) {
  passesExistingOfflineVerifier = false;
  verifierRejectionReason = err.message;
  eligibility = 'REQUIRES_REVIEW';
  eligibilityReason = `VERIFIER_REJECTION: ${err.message}`;
}
```

### 3.1 Eligibility Classification Standard
- **`ELIGIBLE` (0 Records):** Requires a successful return from `validateCorrectionEligibility()` confirming three-way binding across manifest, crosswalk, component ledger, and source coordinate. Under the existing verifier, zero mutations qualify.
- **`INELIGIBLE` (Asset: 111, Liability: 3,630):** Applied strictly when `currentRepresentedValue === proposedValue`, indicating the database already represents the authoritative disclosure accurately without requiring mutation.
  - *Asset Dimension (111):* Group 5 genuine zeros evaluate to 0 in the schema-generated column, matching the Form 26 zero disclosure.
  - *Liability Dimension (3,630):* Group 1 (3,334 positive), Group 2 (185 genuine zero), and Group 5 (111 genuine zero) are already accurately stored in Chunk SQL column 12.
- **`REQUIRES_REVIEW` (Asset: 4,412, Liability: 893):** Mandatory whenever a mutation is required but available evidence cannot satisfy the existing verifier.

## 4. Source and Identity Handling (§4)

Directive 072 resolves the four specific findings from Directive 071 truthfully without fabricating evidence:

### Finding A: Missing Component Ledgers (3,403 Records)
- **Problem:** Only 1,120 records have component-level breakdowns in `scratch/w021_5_directive_047_1120_component_ledger.json`. The remaining 3,403 records belong to states where affidavits only disclosed total values or where component data was not extracted into a component ledger.
- **Resolution:** No synthetic component values or ledger entries were fabricated. All 3,403 records requiring ledger verification fail closed with `MISSING_LEDGER_ENTRY` and remain `REQUIRES_REVIEW`.

### Finding B: Lok Sabha Source Identity (543 Records)
- **Problem:** 543 records in `data/seed/mp-profiles.ts` represent Members of Parliament. They contain parliamentary constituency numbers (`pcNo`), not Assembly numbers (`acNo`). The verifier's identity check (`parsed.acNo !== expectedAcNo`) strictly rejects them.
- **Resolution:** Parliamentary constituencies were not coerced into Assembly numbers. Records fail closed with `MISSING_REQUIRED_IDENTITY_FIELD: Constituency number (acNo) missing in source object` and remain `REQUIRES_REVIEW`.

### Finding C: Nested `financialHistory` (1,120 Records)
- **Problem:** Component seed files (AP, AS, KL, PY, TN, WB) store candidate financials in a nested `financialHistory: [...]` array. Flat lexical parsing at top-level returns `undefined`. Furthermore, records such as `0215b22e-aff-00001575` (Kerala Advocate C V Santhakumar) contain multi-year histories where 2026 values differ from 2021 manifest values.
- **Resolution:** Flat parsing correctly returns `undefined`, triggering `SOURCE_VALUE_UNAVAILABLE` in the verifier. No disclosure is inferred from an absent flat property. All affected records fail closed and remain `REQUIRES_REVIEW`.

### Finding D: Karnataka Source-Coordinate Conflict (1 Record)
- **Problem:** Affidavit `0215b22e-aff-00001430` has manifest candidate name `B C Janardhan Reddy`, but source file `data/seed/karnataka-mla-profiles.ts:1156` contains `G. Janardhan Reddy`.
- **Resolution:** The conflict was not resolved by arbitrarily selecting one name. The conflict is explicitly preserved with `hasSourceConflict: true`, triggering `UNRESOLVED_SOURCE_CONFLICT` in the verifier, and the record remains isolated in `REQUIRES_REVIEW`.
