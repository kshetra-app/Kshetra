2. **Bitwise SHA-256 Digest Verification:**
   - `tsSha256`: `5759ceea56cb119974ce441fa1249cc58d4bfb7a3157814fa31cb28b5726a648`
   - `apSha256`: `a88a01a26875bd7744c8e54695a2a39662f7b36753938b7fc94a2eff822080fa`
   Every manifest entry declares `referenceDocumentPath` and `sourceArtifactSha256`. At validation time, `CHECK_6` reads the actual file from disk, calculates its SHA-256, and asserts identity.
3. **Derivation of Source Passages from Resolved Artifacts:**
   `buildManifest()` invokes `parseStatutoryTableBExtract(filePath)` to parse the actual text lines on disk into structured entries (`entryNo`, `name`, `statutoryName`, `extent`, `rawPassage`). It then constructs `sourcePassageExtract` directly from these parsed source objects.
4. **Field Separation & Evidentiary Role Labeling:**
   Every record maintains separate fields:
   - `sourcePassageExtract`: Verbatim or faithfully transcribed statutory extract from the resolved artifact.
   - `manuallyAuthoredSummary`: Engineering notes describing what the source establishes and administrative context.
   - `evidentiaryRoleLabel`: Explicitly set to `"VERBATIM_STATUTORY_EXTRACT_REPRESENTS_ASSEMBLY_EXTENT_NOT_POSTAL_CONTAINMENT"`.
5. **Authenticity vs Integrity Distinction:**
   The validator strictly distinguishes artifact byte integrity (`sourceArtifactIntegrityStatus: 'VERIFIED_SHA256_MATCH'`) from official gazette authenticity (`officialPublicationAuthenticityStatus: 'UNVERIFIED_EXTERNAL_PUBLICATION_NOT_CHECKED_IN'`). A hash matches the checked-in file; it does not substitute for physical gazette audit.
