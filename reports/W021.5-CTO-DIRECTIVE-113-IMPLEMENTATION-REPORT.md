## 3. Workstream B — Adversarial Trust-Boundary Hardening & Options Audit

### 3.1 Confounded Test Pattern Remediation
In CTO Directive 111 Test 2.6, bypass mode flags (`testMode: true`, `allowOverrides: true`, `productionVerificationMode: false`, `bypassLedgerValidation: true`) were tested by passing them alongside `expectedHashOverride: 'TAMPERED'`. Because `expectedHashOverride` was itself rejected as a forbidden key, the test passed due to the expectedHashOverride rejection, failing to prove that each bypass flag in isolation was ineffective.

In Directive 113:
1. **Isolated Bypass Tests:** Each flag is tested strictly in isolation against all 4 public verifier entry points without `expectedHashOverride`.
2. **Options Validation:** Decided and codified which non-trust configuration options are legitimately supported:
   - Supported option: `repoRoot` (non-empty string pointing to an existing directory on disk).
   - All other options, flags, and unknown keys are strictly forbidden and rejected.

### 3.2 Hardening of `assertNoCallerTrustOverrides`
`scripts/internal/reconcile_engine.mjs` was hardened with five layers of defensive validation:
1. **Non-Object Input Validation:** Rejects non-object inputs (`null`, primitives, arrays, booleans) with `CALLER_TRUST_OVERRIDE_PROHIBITED`.
2. **Prototype Chain Scanning (`key in options`):** Detects both own properties and prototype-inherited properties to prevent prototype pollution bypasses.
3. **Canonical Forbidden Overrides:**
   - `FORBIDDEN_TRUST_OVERRIDES`: `expectedHashOverride`, `expectedHeadOverride`, `expectedEvidenceCommitOverride`, `expectedTreeStateOverride`, `expectedEarnedCompletionOverride`, `expectedBlockedCompletionOverride`, `skipHashVerification`, `skipGitVerification`, `allowOverrides`, `testMode`.
4. **Expanded Trust Material Overrides:**

5. **Unknown Key Rejection:** Enforces `APPROVED_PUBLIC_OPTIONS = ['repoRoot']`. Any option not in this whitelist is rejected with `CALLER_TRUST_OVERRIDE_PROHIBITED`.
6. **Path Traversal & Sanity:** Enforces `repoRoot` must be a valid, existing directory string.

### 3.3 Public Entry Point Sanitization
In `scripts/reconcile_execution_ledger.mjs`, `reconcileExecutionLedger(options)` sanitizes its arguments and forwards only `{ repoRoot }` to `reconcileExecutionLedgerCore`, preventing any internal option leakage.
