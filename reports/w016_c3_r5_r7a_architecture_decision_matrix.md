## 1. Objective & Scope

This document provides the formal trade-off evaluation matrix comparing four spatial delivery technologies for PANIN:
1. **Option A:** Dynamic MVT generated by Fastify/PostGIS (`ST_AsMVT`)
2. **Option B:** Pre-generated versioned MVT artifacts behind CDN
3. **Option C:** PMTiles single-file archive delivery on object storage via HTTP Range Requests
4. **Option D:** Governed Multi-Tier Hybrid Architecture (PostGIS Master + Pre-Rendered PMTiles/MVT for Maps + Fastify API for Spatial Queries)

The evaluation is conducted across 15 technical, operational, governance, and financial dimensions to give the CTO complete information for the final architectural determination.

## 3. Explicit Version Selection Contract

To prevent the runtime system from ever silently converting one geographic regime into another, the architecture mandates an explicit **Version Selection Contract** governing all runtime query and delivery paths:

```
[ Incoming Request ]
        │
        ├── Has ?scenario_id=... ────────────────────────> [ REGIME E: Scenario Geography ]
        │                                                  (Quarantined, status=SCENARIO, non-statutory)
        │
        ├── Has ?version_id=... OR ?version_code=... ────> [ REGIME C: Explicit Version Selection ]
        │                                                  (Exact immutable version record lookup)
        │
        ├── Has ?as_of=YYYY-MM-DD ───────────────────────> [ REGIME B: Historical As-Of Date ]
        │                                                  (Temporal interval valid_from <= T < valid_to)
        │
        ├── Has ?regime_id=... (Future Enacted) ─────────> [ REGIME D: Future Anticipated Regime ]
        │                                                  (valid_from > CURRENT_DATE, is_current=false)
        │
        └── No Special Parameters (Default) ─────────────> [ REGIME A: Current Statutory Geography ]
                                                           (is_current=true, valid_to IS NULL, active)
```

### Regime Definitions & SQL Guarantees

1. **Regime A: Current Statutory Geography (Default)**
   * **Scope:** The active, legally valid boundaries currently in effect across India.
   * **SQL Predicate:**
     ```sql
     WHERE is_current = true
       AND (valid_to IS NULL OR valid_to > CURRENT_DATE)
       AND temporal_classification != 'scenario'
     ```
   * **Fail-Closed Rule:** If an entity has no active version where `is_current = true`, the system returns `404 Not Found`. It must **never** substitute a historical or scenario version.

2. **Regime B: Historical / As-Of-Date Geography**
   * **Scope:** Statutory geography as it legally existed on a specific calendar date in history.
   * **SQL Predicate:**
     ```sql
     WHERE valid_from <= :as_of_date::date
       AND (valid_to > :as_of_date::date OR valid_to IS NULL)
       AND temporal_classification = 'historical_statutory_baseline'
     ```
   * **Fail-Closed Rule:** If the entity was not yet formed or was dissolved as of the requested date, returns `404 Not Found`. Response header includes `x-geography-temporal-classification: historical`.

3. **Regime C: Explicit Version Selection**
   * **Scope:** Direct fetch of a specific, immutable version record by UUID or unique version code.
   * **SQL Predicate:**
     ```sql
     WHERE id = :version_uuid OR version_code = :version_code
     ```
   * **Fail-Closed Rule:** Strict 404 if record does not exist.

4. **Regime D: Future Anticipated Statutory Regime**
   * **Scope:** Legally enacted delimitation or reorganization orders scheduled to take effect on a future date.
   * **SQL Predicate:**
     ```sql
     WHERE delimitation_regime_id = :regime_id
       AND valid_from > CURRENT_DATE
       AND is_current = false
     ```
   * **Fail-Closed Rule:** Delivered with explicit response header `x-geography-regime: future_enacted`. Must never be mixed with current active geography.

5. **Regime E: Scenario / Simulation Geography**
   * **Scope:** Non-statutory algorithmic models, draft boundary proposals, or civic sandbox simulations.
   * **SQL Predicate:**
     ```sql
     WHERE dataset_version_id = :scenario_dataset_id
       AND status = 'SCENARIO'
     ```
   * **Fail-Closed Rule:** Completely segregated. Inaccessible via standard public endpoints. Requires dedicated `/api/v1/geo/scenarios/:scenarioId/...` routes and carries watermark metadata.

## 4. Governance Envelope: Database Storage vs Runtime Payload

To protect mobile network bandwidth while guaranteeing statutory auditability, the architecture separates the database governance model from the runtime feature properties.

### Tier 1: Runtime Tile Feature Properties (Embedded in MVT / Vector Tiles)
Carried within every individual vector tile feature. Strictly limited to minimal identifiers and display attributes to keep tile payloads under 50–80 KB:

```json
{
  "entity_id": "TS-MDL-501",
  "version_id": "97e6bece-ca9d-4c31-b51f-50dcbefd927a",
  "name": "Rajendranagar",
  "status": "DERIVED",
  "is_current": false,
  "regime_type": "historical_statutory_baseline"
}
```

### Tier 2: Comprehensive Governance Payload (Fetched via Detail API)
Fetched lazily on-demand when a user taps a boundary or requests statutory audit evidence (`GET /api/v1/geo/entities/:entityType/:id/metadata`):

```json
{
  "entity_id": "TS-MDL-501",
  "entity_type": "mandal",
  "version_id": "97e6bece-ca9d-4c31-b51f-50dcbefd927a",
  "version_code": "TS-MDL-501-2016-V1",
  "dataset_version_id": "tgrac_mandals_2016_v1_topologically_repaired",
```

## 5. Offline & Degraded Mode Resilience Matrix

| Failure Mode | System Response | Non-Negotiable Invariant |
| :--- | :--- | :--- |
| **Edge CDN Outage** | Mobile client serves boundaries from local SQLite / FileSystem disk cache. If uncached, displays offline notification with bundled national overview (`IN`). | **Never substitutes incorrect or unverified boundary files.** |
| **API Gateway Outage** | Map rendering continues uninterrupted using cached tiles. Point inspection (`locate`) displays "Service temporarily unavailable" without disrupting map canvas. | **Never crashes the mobile UI thread or renders blank canvas.** |
| **Database Outage** | Static tiles and cached API responses continue serving from edge CDN and Redis. Dynamic spatial queries return structured HTTP 503 with error code `DATABASE_FAILURE`. | **Never serves uncommitted or dirty data.** |
| **Tile Missing / Corrupt** | MapLibre leaves the missing tile area transparent with retry affordance. | **Never stretches adjacent tiles or substitutes mismatched geography.** |
| **Temporal Version Missing** | Returns structured HTTP 404 with error code `GEOGRAPHY_VERSION_NOT_FOUND`. | **Never silently defaults a historical date query to current geography.** |
