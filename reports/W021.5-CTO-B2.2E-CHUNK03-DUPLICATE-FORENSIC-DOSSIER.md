## 1. EXECUTIVE VERDICT & RECOMMENDED RESOLUTION

### 1.1 Executive Verdict
Defect **`DQ-W021.5-B2.2E-001`** is a **Source Ingestion Artifact (AST Text Parsing Defect)** caused by textual extraction of an in-memory programmatic patch table (`ENRICHED_PROFILES`) inside `data/seed/karnataka-mla-profiles.ts`.

It is **NOT** a duplicate filing, **NOT** an amended nomination by the Election Commission of India (ECI), and **NOT** duplicate scraping from MyNeta/ADR.

The second tuple (`0215b22e-0001-0000-0000-000000001571`) is a **phantom affidavit artifact** generated when the parser `scripts/generate-b2-2e-forensic-manifests.mjs` extracted a TypeScript in-memory helper object meant only to patch degree/profession in `KA_MLA_PROFILES`. Because the helper object lacked financial attributes, the generator defaulted `total_liabilities = 0`, `total_assets = 0`, and `criminal_cases = 0`.

When executed against `panIN-staging`, PostgreSQL's pre-existing Sprint 14 schema constraint `UNIQUE(candidate_name, ac_no, state_code, election_year)` from Migration 008 (`008_election_affidavits.sql:50`) operated exactly as designed: it committed the authoritative, populated disclosure tuple (`...1535`) and dropped the unpopulated duplicate tuple (`...1571`) via `ON CONFLICT DO NOTHING`.

### 1.2 Recommended Resolution
1. **Formally classify tuple `0215b22e-0001-0000-0000-000000001571` as an invalid ingestion artifact** and retire it from the canonical candidate affidavits population.
2. **Reconcile Ground Truth to 4,523 Unique Canonical Candidate Affidavits** (1,272 distinct affidavits in Chunk 03; 229 in Karnataka).
3. **Keep staging database untouched**: The current state of `public.candidate_affidavits` in staging holds exactly 1,272 valid, verified Chunk 03 records (total 2,468 table rows). No DDL, DML, or database repair is required.
4. **Authorize separate update of read-only checkpoint assertions** (Chunks 03, 04, 05, and Consolidated Gate Check 6) to reflect the true canonical target of 4,523 unique entities.

```sql

  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  state_code TEXT NOT NULL,
  party TEXT NOT NULL,
  election_year INTEGER NOT NULL,

);
```

### 3.2 Semantic Difference: Entity vs Document vs Row
1. **Civic Contest Entity (Canonical Reality):** An assembly candidacy in Indian electoral law is a single political entity. Under ECI statutory rules (Representation of the People Act, 1951), while a candidate may file multiple nomination papers, only one accepted nomination/affidavit determines the candidacy. In Kshetra's model, `candidate_affidavits` enforces a 1:1 relationship with the candidate contest via `UNIQUE(candidate_name, ac_no, state_code, election_year)`.
2. **Source Ingestion Artifacts:** The static repository code contained two AST object declarations due to how developers organized seed enrichment.
3. **Inserted Database Row:** PostgreSQL enforces physical invariants. When executing `INSERT ... ON CONFLICT DO NOTHING`, PostgreSQL inserted Tuple 1 (`...1535`) and dropped Tuple 2 (`...1571`). The database currently contains exactly **one** canonical row for Basavaraj Bommai in Shiggaon (2023).
