## 2. Workstream Details & Technical Implementations

### 2.1 Workstream A: Fail-Closed TypeScript AST Parsing

**Primary File:** `scripts/lib/ast_data_parser.mjs`

```javascript
export function parseTsSource(sourceText, fileName = 'source.ts') {
  const sourceFile = ts.createSourceFile(fileName, sourceText, ts.ScriptTarget.Latest, true, ts.ScriptKind.TS);
  const parseDiagnostics = (sourceFile.parseDiagnostics || []).map((d) => {
    let line = 0;
    let character = 0;
    if (d.file && typeof d.start === 'number') {
      const pos = d.file.getLineAndCharacterOfPosition(d.start);
      line = pos.line + 1;
      character = pos.character + 1;
    }
    const message = typeof d.messageText === 'string' ? d.messageText : d.messageText?.messageText || 'Unknown syntax error';
    return { code: d.code, message, line, character };
  });

  return {
    sourceFile,
    parseDiagnostics,
    syntacticParseSuccess: parseDiagnostics.length === 0,
  };
}
```

- When `syntacticParseSuccess` is `false`, parser functions immediately fail closed, returning `total: 0`, non-empty `parseDiagnostics`, and diagnostic error messages.
- `evaluateAstNode()` explicitly handles:
  - Numeric literals with numeric separators (`1_000_000` -> `1000000`)
  - Negative numbers via `PrefixUnaryExpression` (`-42.5`)
  - Strings with braces, escaped quotes, and double quotes
  - Array and object literals
  - Rejects computed property keys, shorthand properties, spread expressions, and variable identifiers with explicit diagnostics.
