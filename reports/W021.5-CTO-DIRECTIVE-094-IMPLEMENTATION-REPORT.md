## 2. Workstream A — Genuine Acceptance Authentication

### 2.1 Elimination of Arbitrary Token Heuristics
The legacy heuristic in Directive 093 that admitted any token with `length >= 16` as authorized CTO proof has been completely removed. Arbitrary test tokens such as `VALID_SECURE_CTO_TOKEN_1234567890` or long random strings fail closed immediately.

### 2.2 Independent Cryptographic Trust Anchor
To establish a verifiable trust mechanism without relying on the untrusted acceptance record:
- An independent authority registry was established at `governance/authorities/trusted_authorities.json`.
- A trusted CTO root public key anchor was established at `governance/authorities/cto_root_public_key.pem` (Ed25519 format).
- In `scripts/reconcile_execution_ledger.mjs`:
  ```javascript
  export function getCanonicalAcceptancePayload(record) {
    return JSON.stringify({
      milestone: record.milestone,
      taskRef: record.taskRef,
      decision: record.decision,
      adjudicatorIdentity: record.adjudicatorIdentity,
      adjudicatorRole: record.adjudicatorRole,
      adjudicationDate: record.adjudicationDate,
      authorSelfAcceptance: record.authorSelfAcceptance,
      conditions: record.conditions || [],
      findings: record.findings || [],
    });
  }
  ```
  Verification executes `crypto.verify(null, Buffer.from(canonicalPayload, 'utf8'), publicKey, signatureBuffer)` against the trusted public key corresponding to `record.signature.keyId`.

## 3. Workstream B — Semantic Content Validation

### 3.1 GeoJSON Semantic Validation (`validateGeoJsonContent()`)
In `scripts/reconcile_execution_ledger.mjs`, `.geojson` files directly enter `validateGeoJsonContent()`:
- Parses JSON data and verifies `stat.size > 0`.
- Validates root type is `'Feature'` or `'FeatureCollection'`.
- Rejects empty feature collections (`features: []`).
- Validates feature geometries (`Polygon`, `MultiPolygon`, `Point`, `LineString`).
- Validates coordinates: numeric, non-NaN, finite, and bounded within Indian territory (longitude $60^\circ$ to $105^\circ$, latitude $4^\circ$ to $42^\circ$).
- Validates that Polygon linear rings are closed (first coordinate equals last coordinate).
- Scans for duplicate constituency identifiers (such as AC 119 in Telangana), detecting defects and distinguishing syntactic correctness from statutory completeness.

### 3.2 SQL Semantic Validation (`validateSqlContent()`)
- Strips single-line comments (`-- ...`) and block comments (`/* ... */`).
- Rejects comment-only SQL files fail-closed.
- Requires genuine SQL statements containing DDL/DML keywords (`CREATE`, `ALTER`, `INSERT`, `UPDATE`, `DELETE`, `DROP`, `GRANT`, `BEGIN`, `COMMIT`).

### 3.3 Test File Semantic Validation (`validateTestContent()`)
- Strips single-line and multi-line comments.
- Rejects token-only files containing inert test strings (`test`, `assert`, `it`, `describe`) without executable invocations.
- Requires executable test runner invocations (`test(`, `it(`, `describe(`, `runTest(`, `assert.`).

### 3.4 Markdown Semantic Validation (`validateMarkdownContent()`)
- Requires structured headings (`#`, `##`).
- Requires a minimum length of 200 non-comment characters.
- Requires task-relevant domain keywords (`kshetra`, `directive`, `governance`, `task`, `verification`, `audit`, `database`, `milestone`, `specification`, `evidence`).
