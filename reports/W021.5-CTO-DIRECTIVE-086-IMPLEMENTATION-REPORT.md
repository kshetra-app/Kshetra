## 3. Workstream Execution Details

### Workstream A: National Coverage Generator Overhaul
- **Removal of Cycle Inference:** Replaced hardcoded `electionYear` and `electionType` in `AUTHORITATIVE_STATE_SEATS`. Seats are strictly statutory legal numbers totaling 4,123.
- **Structural Affidavit Parsing:** Implemented `inspectAffidavits(stateCode)` inspecting `{ id, candidateName, acNo, constituencyName, stateCode, sourceUrl }` from `apps/mobile/stores/affidavits.ts`. Total valid affidavits: 28 across 8 states (TS: 17, AP: 2, KA: 2, MH: 1, TN: 2, KL: 1, WB: 1, UP: 2); 0 in remaining 23 states.
- **Actual Structured Profile Counting:** Discarded the assumption that profile count equals constituency count. Audited literal profiles in `*-mla-profiles.ts`:
  - Karnataka: 171 valid profiles (171/224).
  - Maharashtra: 240 valid profiles (240/288).
  - National Total Statutory Profiles: 3,812 / 4,123 (92.5%).
  - Extra Non-Statutory Placeholders: 153 (151 in DL + 2 in HP).
- **Deep GeoJSON Inspection:** Validated FeatureCollection, polygon/multipolygon geometry types, non-empty coordinate arrays, bounding box containment within India [65°E–100°E, 5°N–40°N], and AC number linkage. Only Telangana (`TS`) has valid GeoJSON in `data/geo` (120 features, 119 linked ACs, 0 errors).

### Workstream B: Removal of State-Code Election-Year Inference
- Removed lines 287–293 of `apps/api/src/services/stateData.ts`. If no year-specific field (`winner2025`..`winner2020` or `c.electionYear`) is present, `year = null` is strictly preserved.
- Bound winner, runner-up, votes, and margin strictly to the same year term.
- Preserved `electionType: 'GENERAL' | 'BYPOLL' | null` without defaulting to `'GENERAL'`.
- Implemented null-safe sort for `elections[]` ordering chronologically descending without converting unknown years into 0 or artificial dates.

### Workstream C: Contract Hardening & Mobile Validation
- Fastify route schema in `apps/api/src/routes/constituencies.ts` updated to allow nullable `electionType`.
- Mobile client validator `validateConstituencyDetail` in `apps/mobile/lib/api/endpoints/constituencies.ts` updated to throw `ApiValidationError` on invalid types and preserve `null`.
- In `apps/mobile/app/constituency/[id].tsx`, section-level provenance badges were introduced:
  - Electoral Result Card: `'Verified Electoral API'` when live API result exists, `'Offline Result Seed'` when offline.
  - Representative Card: `'Offline Profile Seed'`.
  - Uncontested elections render `'0 (Uncontested)'` margin.
- Consumer audit re-verified: zero active mobile screens rely on `election2023`.

### Workstream D: Canonical Architecture Readiness Package
