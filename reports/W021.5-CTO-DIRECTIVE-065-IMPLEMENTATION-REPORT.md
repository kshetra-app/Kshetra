## 2. Row-Level Source-Value Eligibility Hardening

In `scripts/verify_financial_remediation.mjs`, `validateCorrectionEligibility()` and its orchestration were comprehensively hardened to enforce an unbroken, 10-point row-level evidence chain:

1. **Exact Manifest Identification:** The correction ID must match exactly one canonical manifest record (`CORRECTION_ID_NOT_IN_MANIFEST`).
2. **Deterministic Target UUID Binding:** The correction must be mapped to the same target candidate UUID by both the crosswalk and the component ledger (`LEDGER_CROSSWALK_UUID_MISMATCH`).
3. **Original Represented Value Parity:** The declared original value in the correction must match the manifest field bitwise (`CORRECTION_ORIGINAL_VALUE_MISMATCH`, `INELIGIBLE_CORRECTION_ORIGINAL_VALUE`).
4. **Mutually Consistent Classification:** The correction classification (`POSITIVE_RESTORATION`, `MISSING_DISCLOSURE`, `GENUINE_ZERO`), target field, original value, intended value, and source evidence must be mutually consistent.
5. **Independently Verified Positive Restoration:** A positive asset or liability restoration must have an independently verified, record-bound source value that matches both the ledger authoritative source total and the intended restored total (`SOURCE_RESTORED_VALUE_MISMATCH`, `SOURCE_TOTAL_MANIFEST_MISMATCH`, `SOURCE_TOTAL_LEDGER_MISMATCH`).
6. **Affirmative Missing Disclosure Evidence:** A missing disclosure must be supported by affirmative source evidence. Ingestion zero-coercion is not proof of missing disclosure. Positive source totals can never be converted to missing/null (`POSITIVE_TOTAL_MUTATION_FORBIDDEN`).
7. **Genuine Zero Invariance:** A genuine zero disclosed in source filings cannot be coerced to NULL (`GENUINE_ZERO_COERCION_FORBIDDEN`), and missing disclosures cannot be fabricated as zero (`ZERO_FABRICATION_FORBIDDEN`).
8. **Mandatory Source Coordinates:** Every correction must provide non-empty `sourceFile` and `sourceLocation` (1-based line number) (`MISSING_SOURCE_COORDINATE`).
9. **Record Boundary & Identity Parity:** Source line coordinates must resolve to an object containing the exact `candidateName` and `acNo` (`SOURCE_COORDINATE_MISMATCH`, `MISSING_REQUIRED_IDENTITY_FIELD`).
10. **Unresolved Conflict Blocking:** Any correction record with `hasSourceConflict === true` immediately halts verification with `UNRESOLVED_SOURCE_CONFLICT`.

## 3. AST Containment & Boundary Integrity

In `scripts/verify_financial_remediation.mjs`:

### 3.1 Canonical Path Validation (`safeCanonicalPath`)
- Uses `fs.realpathSync` to resolve symlinks and real filesystem paths.
- Rejects UNC network paths (`\\\\`, `//`) and drive-hopping.
- Asserts that both the normalized relative path and canonical realpath strictly start with the approved repository root directory (`realRepoRoot + path.sep`).
- Fails closed with `PATH_OUTSIDE_REPO_ROOT` on any traversal or escape attempt.

### 3.2 Bounded Lexical AST Scanner
- Character-by-character scanner tracking bracket depth (`{` vs `}`) and parenthesis depth.
- Strips single-line (`//`) and multi-line (`/* ... */`) comments before tokenization, preventing commented-out properties from being extracted.
- Properly handles single quotes (`'`), double quotes (`"`), and template literals (`` ` ``), including escaped quotes (`\'`, `\"`) and escaped backslashes (`\\`).
- Isolates nested sub-object properties (depth > 1), ensuring that nested objects (e.g. `spouseAssets: { totalAssets: ... }`) are never conflated with top-level candidate properties.
- Strictly bounds extraction to the object literal enclosing the specified source line, preventing bleed into neighboring candidate records.
- Strips numeric separators (`_`) and validates integer bounds with `Number.isSafeInteger()` (`INVALID_NUMERIC_VALUE`).
- Enforces mandatory identity properties (`candidateName` and `acNo`) on extracted records.

   - Updated `computeWealthGrowth` to return `{ isAvailable: false, fromAssets, toAssets, absoluteGrowth: null, percentGrowth: null, annualizedGrowth: null }` when either observation is null.

2. **`apps/mobile/lib/legislatorProfileTypes.ts`:**
   - Converted `LegislatorFinancials` `totalAssets` and `totalLiabilities` to `number | null`.
   - Hardened local `formatINR` and `detectAllRedFlags` to guard against null liabilities and assets.
3. **`apps/mobile/components/legislator/FinancialBreakdownCard.tsx`:**
   - Removed all `|| 0` fallbacks.
   - Renders explicit "Assets not disclosed" banner when `totalAssets === null`.
   - Displays "Component breakdown not itemized in filing" when components are missing/null.
   - Renders a subtle dashed 2px baseline bar for undisclosed timeline observations.
4. **`apps/mobile/components/AffidavitCard.tsx`:**
   - Guarded `latestGrowth && latestGrowth.percentGrowth != null && (...)` before `.toFixed(0)`.
   - Renders "Not Disclosed" badge for null assets and liabilities.
5. **`apps/mobile/components/WealthTimeline.tsx`:**

   - Guards `growth.percentGrowth != null` and `growth.annualizedGrowth != null`.
6. **`apps/mobile/app/legislator/[id].tsx`:**
   - Removed `|| 0` fallbacks.
   - Computes `netWorth = (hasBoth ? totalAssets - liabilities : null)`.
   - Displays "Not Disclosed" when null.
7. **`apps/mobile/app/parliament/index.tsx`:**
   - Updated local `formatINR` helper to handle `null | undefined`.
8. **`apps/mobile/stores/affidavits.ts`:**
   - `getConstituencyIntegrity`: filters disclosed candidates (`a.totalAssets != null`) for `avgAssets` denominator; includes `assetsDisclosedCandidatesCount`.
   - `getCrorepatiCount`: filters disclosed candidates; returns `{ total, disclosedCount, crorepatis, percent }`.
9. **`data/seed/telangana-mla-profiles.ts`, `apps/mobile/lib/mpTypes.ts`, `apps/mobile/lib/seedDataLoader.ts`:**
   - Converted financial interface fields to `number | null` for full cross-module consistency.
