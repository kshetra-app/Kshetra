## 2. Phase A — CI Test Failure Remediation & Strict Assertion Restoration

### 2.1 Root Cause Diagnosis of CI Run `39327802514`
Inspection of failed GitHub Actions Job `118318036630` in workflow run `39327802514` identified:
- **Failed Assertion:** `apps/api/src/__tests__/moderation.test.ts:374`:
  `expect(other.statusCode).toBe(200)` received `503`.
- **Root Cause:** In GitHub Actions runners, no `.env` file exists. Consequently, `process.env.SUPABASE_URL` is undefined, causing `isSupabaseConfigured` in `apps/api/src/lib/supabase.ts` to initialize to `false`. Furthermore, `civic-mutations.test.ts` previously called `setSupabaseConfiguredForTesting(false)` in its `afterAll` hook without restoring the previous state, permanently poisoning `isSupabaseConfigured` for subsequent test suites in the worker.
- **Fail-Closed Route Semantics:** When `isSupabaseConfigured === false`, `POST /api/v1/moderation/block` immediately returns HTTP 503 `DATABASE_UNAVAILABLE`. While this 503 behavior is **strictly correct and mandatory** for live unconfigured production environments (as verified by `w011-fail-closed.test.ts`), unit test suites testing route handlers expect standard test environment configuration.

### 2.2 Test Environment Repair
1. **Fallback Test Environment Configuration:**
   In `apps/api/jest.config.js` and `.github/workflows/ci.yml`, standard non-production test fixture credentials are now injected:
   ```javascript
   process.env.SUPABASE_URL = process.env.SUPABASE_URL || 'https://test-fixture.supabase.co';
   process.env.SUPABASE_ANON_KEY = process.env.SUPABASE_ANON_KEY || 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...dummy_signature_for_test_environment_only';
   ```
2. **State Leak Elimination in `civic-mutations.test.ts`:**
   Saved `originalConfigured = isSupabaseConfigured` in `beforeAll` and restored `setSupabaseConfiguredForTesting(originalConfigured)` in `afterAll` and after the unconfigured describe block, preventing global test runner contamination.
3. **Dedicated Test Suite Setup:**
   In `moderation.test.ts`, `routes-stubs.test.ts`, and `dm-rate-limits.test.ts`, ensured `setSupabaseConfiguredForTesting(true)` during suite execution with full restoration in `afterAll`.

### 2.3 Elimination of Permissive Assertions
In Directive 115, several assertions had been widened to `expect([200, 503]).toContain(...)`. Under Directive 116 Section 3, all permissive assertions have been audited and replaced with strict assertions:
1. `apps/api/src/__tests__/moderation.test.ts`:
