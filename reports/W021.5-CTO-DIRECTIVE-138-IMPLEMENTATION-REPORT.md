## 2. Workstream A — Mobile Persistent SQLite Offline Sync Remediation (`CRIT-I01-01` / `REQ-SYS-001`)

### 2.1 Observed Defects
- Prior tests in `tests/mobile-sqlite-offline-sync.test.mjs` directly used `MemorySqliteAdapter`. Testing restart-persistence on the same in-memory adapter did not prove that queued mutations survive process termination and restart on a real disk-backed SQLite database.
- `apps/mobile/lib/sync/syncEngine.ts` marked queued mutations as successfully synced when `!this.dispatchHandler` was true, producing a false-positive sync status when no network or dispatch mechanism was configured.

### 2.2 Substantive Remediation
1. **Persistent SQLite Adapter (`apps/mobile/lib/database/betterSqliteAdapter.ts`):**
   - Implemented a complete disk-backed SQLite adapter using `better-sqlite3` for Node/CLI/test environments.
   - Wired `BetterSqliteAdapter` into `apps/mobile/lib/database/database.ts` to automatically select genuine disk-backed SQLite when running under Node or test environments, while preserving Expo SQLite for native mobile runtime.
2. **Crash & Interruption Recovery (`apps/mobile/lib/sync/mutationQueue.ts`):**
   - Implemented `recoverInFlight()` which scans for mutations interrupted in the `IN_FLIGHT` state upon engine startup and safely resets them to `PENDING` so no mutations are lost or stuck.
3. **Fail-Closed Dispatch Handler (`apps/mobile/lib/sync/syncEngine.ts`):**
   - Eliminated the false-positive path where absent dispatch handlers marked operations as synced.
   - When no dispatch handler is configured, the engine fails closed, returns `DISPATCH_HANDLER_MISSING`, and leaves mutations in `PENDING` state.
4. **Comprehensive Persistent SQLite Test Battery (`tests/mobile-sqlite-offline-sync.test.mjs`):**
   - Completely rewrote the test battery to run 12 comprehensive tests on actual disk SQLite (`.tmp_test_offline_sync.db`):
     - Test 1: Fresh disk database and v1 schema migration.
     - Test 2: Migration from v1 to v2 schema with column preservation.
     - Test 3: Close database handle, re-open on new adapter instance, and assert queued mutations persist bitwise across process restart.
     - Test 4: Duplicate idempotency key rejection.
     - Test 5: Successful dispatch and completed state transition.
     - Test 6: Unconfigured dispatch handler fails closed and preserves mutations in PENDING state.
     - Test 7: Network/server retry policy and dead-letter queue transition after maximum retries.
     - Test 8: Engine startup recovery of interrupted IN_FLIGHT mutations.
     - Test 9: Deletion tombstones and conflict resolution.
     - Test 10: Corrupted persisted payload handling (preserves error without crashing engine).
     - Test 11: Idempotent replay safety with 0 duplicate writes.
     - Test 12: Server authorization failure (HTTP 401/403) handling.
