## 3. P0 — Stage 3 Schema Contract Foreign Key Concordance

### 3.1 DDL & Contract Alignment
Migration 066 line 18 explicitly defines:
```sql
constituency_id UUID NOT NULL REFERENCES public.constituencies(internal_id) ON DELETE RESTRICT
```
The previous schema contract erroneously stated `public.constituencies(id)`.
In `reports/w021_5_schema_contract_specification.json`, the specification for `stage3_constituency_demographics` was updated:
```json
"foreignKeys": [
  {
    "column": "constituency_id",
    "references": "public.constituencies(internal_id)"
  }
]
```

### 3.2 Four-Identity Crosswalk Isolation
The crosswalk builder (`scripts/build_constituency_4123_crosswalk.mjs`) strictly separates:
1. `statutoryCompositeCode`: Composite identity string (e.g., `'AP-AC-1'`) from Migration 059 DDL.
2. `canonicalCode`: Zero-padded statutory code (e.g., `'AP-AC-001'`), stored in `public.constituencies.id` (TEXT).
3. `reproducibleNamespaceUuid`: Offline reproducible RFC 4122 UUIDv5 generated via namespace `6ba7b810-9dad-11d1-80b4-00c04fd430c8` and name `constituency:${stateCode}:${acNo}`.
4. `targetInternalUuid`: Target database surrogate primary key `internal_id` (UUID generated via `gen_random_uuid()`), which remains `null` until authorized read access to staging/production is granted.

Automated assertions in `tests/database-criteria-identity-reconciliation.test.mjs` verify both DDL concordance and 4-identity isolation (CRIT-E01-02 tests 9 and 10, both PASS).
