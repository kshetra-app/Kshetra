## 1. EXECUTIVE CONTEXT & ROOT CAUSE OF THE "2,500 VS 2,300" DISCREPANCY

In response to CTO Directive `W021.5-CTO-B2.2D-CH02-PARTITION-RECON-001`, an exhaustive forensic audit of the B2.2-D deterministic generator scripts, the approved SQL chunk artifacts, and the canonical manifests was conducted to establish why earlier reports referenced Chunk 02 as "Persons 1–2,500" while the physical artifact contains exactly 2,300 records.

### The Findings
1. **The Generator Script (`scratch/generate_deterministic_b2_2d_package.mjs`):**
   - Lines 189–190:
     ```javascript
     // PERSONS CHUNKS (Chunks 02–05, ~2300 rows each)
     const PERSON_CHUNK_SIZE = 2300;
     ```
   - To divide the total **9,083 canonical persons** into 4 balanced execution chunks, the generator configured `PERSON_CHUNK_SIZE = 2300` ($\lceil 9083 / 4 \rceil \approx 2271$).
   - This produced 4 chunks:
     - **Chunk 02:** Rows 1 to 2,300 (2,300 records)
     - **Chunk 03:** Rows 2,301 to 4,600 (2,300 records)
     - **Chunk 04:** Rows 4,601 to 6,900 (2,300 records)
     - **Chunk 05:** Rows 6,901 to 9,083 (2,183 records)
     - **Total:** $2,300 + 2,300 + 2,300 + 2,183 = \mathbf{9,083\text{ persons}}$.
2. **The Actual Approved Physical Artifacts:**
   - Every physical SQL chunk file was generated with an explicit self-documenting header:
     - `065_b2_2d_chunk_02_persons_part1.sql` (Line 3): `-- Rows: 2300 (Persons 1 to 2300 of 9083)`
     - `065_b2_2d_chunk_03_persons_part2.sql` (Line 3): `-- Rows: 2300 (Persons 2301 to 4600 of 9083)`
     - `065_b2_2d_chunk_04_persons_part3.sql` (Line 3): `-- Rows: 2300 (Persons 4601 to 6900 of 9083)`
     - `065_b2_2d_chunk_05_persons_part4.sql` (Line 3): `-- Rows: 2183 (Persons 6901 to 9083 of 9083)`
   - The approved SHA-256 for Chunk 02 (`bcec94bea5fad0f1d5e294f973e7f22a60ce8815cf319d49651ba375585f01fa`), its byte size (`1,075,523 bytes`), and its line count (`32,255 lines`) belong to this **exact 2,300-row file**. The file was never modified.
3. **Root Cause of the Discrepancy:**
   - When the remediation dossier (`W021.5-B2.2-D_REMEDIATION_PACKAGE_DOSSIER.md`) was authored, the markdown manifest table included the descriptive text:
     - `Persons 1–2,500`
     - `Persons 2,501–5,000`
     - `Persons 5,001–7,500`
     - `Persons 7,501–9,083`
   - This was a **human documentation error / descriptive copy-paste mistake** in the Markdown table column. The author erroneously assumed the nominal 2,500 interval (used conceptually in the candidacies table below it) applied to persons.
   - **No records were ever lost, dropped, or skipped.** The underlying data files and the deterministic generator have always partitioned persons at `2,300` per chunk.
