## 3. Workstream A: Elimination of Forgeable Trust Tokens & Test Seam Isolation

### 3.1 Vulnerability Analysis of `Symbol.for(...)`
In ECMAScript, `Symbol.for(key)` looks up the symbol in a global symbol registry that spans all execution contexts (including iframes, workers, and modules). If a protection mechanism relies on:
```javascript
const TEST_HARNESS_PROTECTION_TOKEN = Symbol.for('KSHETRA_TEST_ONLY_HARNESS_PROTECTION_TOKEN');
```
Any caller can trivially obtain an identical symbol by invoking:
```javascript
const forgedToken = Symbol.for('KSHETRA_TEST_ONLY_HARNESS_PROTECTION_TOKEN');
```
This is not a cryptographic secret or trust boundary; it provides zero authorization defense against malicious or untrusted in-process callers.

### 3.2 Structural Seam Isolation Architecture
To resolve this fundamentally, we established a strict physical architecture:

## 5. Workstream C: Canonical Symlink Containment & Adversarial Negative Tests

### 5.1 Hardened Path Containment Logic
In `scripts/capture_test_execution.mjs` and `scripts/reconcile_execution_ledger.mjs`, `assertPathContainedInRoot` enforces a four-stage containment check:
```javascript
export function assertPathContainedInRoot(filePath, repoRoot = REPO_ROOT) {
  // 1. Prohibit absolute paths and drive letters
  if (path.isAbsolute(filePath) || /^[a-zA-Z]:[\\\/]/.test(filePath) || /^[\\\/]/.test(filePath)) {
    throw new Error(`Path containment violation: "${filePath}" is an absolute path. Manifest outputLogPath must be repository-relative.`);
  }

  // 2. Lexical containment within root
  const resolvedPath = path.resolve(repoRoot, filePath);
  const normalizedRoot = path.resolve(repoRoot);
  if (!resolvedPath.startsWith(normalizedRoot + path.sep) && resolvedPath !== normalizedRoot) {
    throw new Error(`Path containment violation: "${filePath}" traverses outside repository root.`);
  }

  // 3. Existence on disk
  if (!fs.existsSync(resolvedPath)) {
    throw new Error(`Path containment violation: Log file does not exist at "${resolvedPath}".`);
  }

  // 4. Canonical containment (symlink / junction dereferencing)
  const realTargetPath = fs.realpathSync(resolvedPath);
  const realRepoRoot = fs.realpathSync(normalizedRoot);
  if (!realTargetPath.startsWith(realRepoRoot + path.sep) && realTargetPath !== realRepoRoot) {
    throw new Error(`Path containment violation: "${filePath}" resolves through symlink outside repository root ("${realTargetPath}").`);
  }

  return { resolvedPath, realTargetPath };
}
```

### 5.2 Sibling Directory Prefix Defense
Notice `realRepoRoot + path.sep`. If `realRepoRoot` is `C:\repo`, a target `C:\repo-evil\log.txt` would satisfy `realTargetPath.startsWith('C:\\repo')` if the trailing separator was omitted. The hardened check requires `realRepoRoot + path.sep`, preventing sibling prefix bypasses.

### 5.3 Genuine Symlink-Escape Adversarial Fixture
Standard Windows symlinks require administrator privileges, causing `EPERM` in non-elevated CI environments. However, Windows directory junctions (`fs.symlinkSync(dir, link, 'junction')`) succeed without administrative rights and are fully dereferenced by `fs.realpathSync`.

In `tests/political-intelligence-directive-108.test.mjs` (and Suite 107):
1. A temporary directory `kshetra-ext-symlink-*` is created in `os.tmpdir()` outside the repository root.
2. A valid log file `external.log` is written inside it.
3. An internal junction `temp-symlink-dir` is created inside the repository pointing to `kshetra-ext-symlink-*`.
4. A manifest fixture referencing `temp-symlink-dir/external.log` is passed to `validateManifestIntegrity`.
5. The verifier dereferences the junction via `fs.realpathSync`, detects escape outside repository root, and fails closed with:
   `resolves through symlink outside repository root`.
6. Cleanup hooks safely remove the junction and temporary external directory.
