### 1.2 Core Architectural Discovery: Root Cause of the 2,953 Synthetic ID Shift

During CTO review of Directive 024, a critical discrepancy was detected: while the proposed scratch manifest had 4,523 rows and proposed Chunk 03 SQL had 1,272 rows, the report noted that **2,953 synthetic affidavit IDs shifted** after the removed duplicate.

Our forensic investigation in Workstream A has established the exact mathematical and structural root cause:

1. **The Sequential Numbering Flaw in the Generator:**
   In `scripts/generate-b2-2e-forensic-manifests.mjs`, synthetic affidavit IDs were generated in a sequential loop over all seed profiles:
   ```javascript
   let seq = 1;
   for (const profile of allProfiles) {
     const affId = `0215b22e-aff-${String(seq++).padStart(8, '0')}`;
     // ...
   }
   ```
   In the original accepted manifest (4,524 rows), an auxiliary duplicate Bommai profile in `karnataka-mla-profiles.ts` (line 3951) was processed at sequence index 1,571, receiving synthetic ID `0215b22e-aff-00001571`. Every subsequent profile across all states received IDs from `...1572` through `...4524` (exactly 2,953 profiles).

2. **The Generator Patch Shifted All Downstream Manifest IDs:**
   When the generator was modified in Directive 022/024 to skip duplicate candidacies, line 3951 was omitted without advancing the sequence counter `seq`. As a result, the next profile (originally `...1572`) received `...1571`, and every subsequent profile shifted down by 1 (`...1572` $\rightarrow$ `...1571`, ..., `...4524` $\rightarrow$ `...4523`).

3. **The Fatal Cross-Artifact Divergence in Directive 024:**
   In Directive 023 and 024, the proposed Chunk 03 SQL was created by **deleting exactly Line 517** (the tuple with ID `0215b22e-0001-0000-0000-000000001571`), while Chunks 02, 04, and 05 were **left completely untouched**!
   Consequently:
   - Chunk 03 SQL retained the original accepted UUIDs `...1572` through `...2469` (773 tuples).
   - Chunk 04 SQL retained the original accepted UUIDs `...2470` through `...3619` (1,150 tuples).
   - Chunk 05 SQL retained the original accepted UUIDs `...3620` through `...4524` (905 tuples).
   - **Total SQL tuples retaining original accepted IDs:** $773 + 1,150 + 905 = 2,828$ tuples.
   - When compared against the Directive 024 scratch manifest (which had shifted all IDs), **2,952 tuples diverged between the proposed manifest and the proposed SQL chunks**!

4. **The Mathematically & Architecturally Correct Resolution (Stable Identifiers):**
   In enterprise relational databases and distributed systems, deleting an invalid duplicate record must **retire / tombstone the invalid identifier**, NOT renumber every downstream primary key in the database:
   - When `0215b22e-aff-00001571` is deleted, it is simply retired.
   - Candidacies 1 through 1570 retain IDs `...0001` through `...1570`.
   - Candidacies 1572 through 4524 retain IDs `...1572` through `...4524`.
   - **Zero subsequent candidacies inherit `0215b22e-aff-00001571`.**
   - **Zero cross-chunk identity shifts occur.**
   - **Chunk 02 SQL (already deployed to Staging Supabase) remains 100% bitwise invariant.**
   - **Chunks 04 and 05 SQL remain 100% bitwise invariant.**
   - **Chunk 03 SQL has strictly 1 line deleted (Line 517).**
   - **Cross-artifact identity match between Manifest and SQL is exactly 4,523 / 4,523 (100.00%)!**
