## 1. Component-Column Semantics & Final Per-Column Data Contract

### 1.1 Existing Schema Inspection
Inspection of [`supabase/migrations/008_election_affidavits.sql`](file:///c:/Users/Laven/OneDrive/Desktop/Kshetra/supabase/migrations/008_election_affidavits.sql#L19-L26) establishes:
```sql
  -- Assets (in INR)
  self_movable_assets BIGINT DEFAULT 0,
  self_immovable_assets BIGINT DEFAULT 0,
  spouse_movable_assets BIGINT DEFAULT 0,
  spouse_immovable_assets BIGINT DEFAULT 0,
  total_assets BIGINT GENERATED ALWAYS AS (
    self_movable_assets + self_immovable_assets + spouse_movable_assets + spouse_immovable_assets
  ) STORED,
```
- **Nullability:** The four component columns (`self_movable_assets`, `self_immovable_assets`, `spouse_movable_assets`, `spouse_immovable_assets`) **do not have a `NOT NULL` constraint**. They are natively nullable in PostgreSQL.
- **Default Constraints:** Each component column was created with `DEFAULT 0`.
- **Decoupling via `DROP EXPRESSION`:** Once `ALTER TABLE public.candidate_affidavits ALTER COLUMN total_assets DROP EXPRESSION IF EXISTS;` executes, `total_assets` is no longer computed from the four components.
- **Authorization Boundary:** Modifying column default constraints in the DDL (e.g. `ALTER COLUMN ... DROP DEFAULT`) is outside authorized remediation scope. However, PostgreSQL column defaults apply **only when an INSERT omits the column**. Any DML update or insert that explicitly supplies a value (including `NULL`) completely overrides the default.

## 4. Tightened Snapshot Preconditions & Concurrency Architecture

### 4.1 Concurrency & Table-Lock Isolation Guard
To prevent concurrent read or write transactions from interleaving between snapshot capture, schema alteration, and batch update:
1. The migration must execute inside a **single atomic transaction block** (`BEGIN; ... COMMIT;`).
2. Immediate execution of an explicit table lock:
   ```sql
   LOCK TABLE public.candidate_affidavits IN ACCESS EXCLUSIVE MODE;
   ```
3. Setting defensive lock and statement timeouts:
   ```sql
   SET lock_timeout = '5s';
   SET statement_timeout = '30s';
   ```
4. This guarantees that the snapshot created is a bitwise identical representation of the exact table state at the instant remediation begins, with zero possibility of concurrent drift.

### 4.2 Fail-Closed Snapshot Creation and Verification
```sql
-- 1. Fail closed if snapshot already exists
DO $$
BEGIN
  IF EXISTS (
    SELECT 1 FROM information_schema.tables 
    WHERE table_schema = 'public' 
      AND table_name = '_w021_5_candidate_affidavits_pre067_snapshot'
  ) THEN
    RAISE EXCEPTION 'PRE_EXISTING_SNAPSHOT_DETECTED: Table public._w021_5_candidate_affidavits_pre067_snapshot already exists. Aborting execution to prevent stale data reuse.';
  END IF;
END $$;

-- 2. Create snapshot under ACCESS EXCLUSIVE lock
CREATE TABLE public._w021_5_candidate_affidavits_pre067_snapshot AS 
SELECT * FROM public.candidate_affidavits;

-- 3. Validate snapshot population, uniqueness, and bidirectional set correspondence
DO $$
DECLARE
  v_snap_count        INT;
  v_live_count        INT;
  v_snap_dups         INT;
  v_missing_in_snap   INT;
  v_missing_in_live   INT;
  v_snap_asset_sum    BIGINT;
  v_snap_liab_sum     BIGINT;
  v_snap_liab_pos     INT;
  v_snap_liab_zero    INT;
BEGIN
  -- A. Population Counts
  SELECT count(*) INTO v_snap_count FROM public._w021_5_candidate_affidavits_pre067_snapshot;
  SELECT count(*) INTO v_live_count FROM public.candidate_affidavits;
  IF v_snap_count <> 4523 OR v_live_count <> 4523 THEN
    RAISE EXCEPTION 'SNAPSHOT_POPULATION_MISMATCH: Snapshot count (%) or live count (%) <> 4523.', v_snap_count, v_live_count;
  END IF;

  -- B. Uniqueness
  SELECT count(*) - count(DISTINCT id) INTO v_snap_dups FROM public._w021_5_candidate_affidavits_pre067_snapshot;
  IF v_snap_dups <> 0 THEN
    RAISE EXCEPTION 'SNAPSHOT_DUPLICATE_KEYS: Snapshot contains % duplicate IDs.', v_snap_dups;
  END IF;

  -- C. Bidirectional Primary-Key Set Equality
  SELECT count(*) INTO v_missing_in_snap 
  FROM public.candidate_affidavits a 
  LEFT JOIN public._w021_5_candidate_affidavits_pre067_snapshot s ON s.id = a.id 
  WHERE s.id IS NULL;

  SELECT count(*) INTO v_missing_in_live 
  FROM public._w021_5_candidate_affidavits_pre067_snapshot s 
  LEFT JOIN public.candidate_affidavits a ON a.id = s.id 
  WHERE a.id IS NULL;

  IF v_missing_in_snap <> 0 OR v_missing_in_live <> 0 THEN
    RAISE EXCEPTION 'SNAPSHOT_SET_INEQUALITY: Bidirectional key match failed (missing_in_snap: %, missing_in_live: %).', v_missing_in_snap, v_missing_in_live;
  END IF;

  -- D. Pre-State Financial Aggregates
  SELECT 
    coalesce(sum(total_assets), 0),
    coalesce(sum(total_liabilities), 0),
    count(*) FILTER (WHERE total_liabilities > 0),
    count(*) FILTER (WHERE total_liabilities = 0)
  INTO 
    v_snap_asset_sum, v_snap_liab_sum, v_snap_liab_pos, v_snap_liab_zero
  FROM public._w021_5_candidate_affidavits_pre067_snapshot;

  IF v_snap_asset_sum <> 0 THEN
    RAISE EXCEPTION 'SNAPSHOT_PRESTATE_CORRUPT: Snapshot total_assets sum (%) <> 0 (expected pre-migration collapse state).', v_snap_asset_sum;
  END IF;

  IF v_snap_liab_sum <> 170455440078 OR v_snap_liab_pos <> 3334 OR v_snap_liab_zero <> 1189 THEN
    RAISE EXCEPTION 'SNAPSHOT_PRESTATE_CORRUPT: Liabilities aggregate mismatch (sum: %, pos: %, zero: %).', v_snap_liab_sum, v_snap_liab_pos, v_snap_liab_zero;
  END IF;
END $$;
```
