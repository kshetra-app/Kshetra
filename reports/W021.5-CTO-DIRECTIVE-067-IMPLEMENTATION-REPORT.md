## 2. Closure of the Authoritative-Value Loophole (§2)

In `scripts/verify_financial_remediation.mjs`, the production row-level eligibility gate `validateCorrectionEligibility()` was repaired to completely eliminate the loophole where missing or non-matching authoritative ledger fields could allow invalid transitions:

### 2.1 Explicit Authoritative Field Presence Check
Before checking values, `validateCorrectionEligibility()` asserts that the ledger entry explicitly declares the authoritative field (either via top-level `authoritativeTotalAssets/Liabilities`, `targetTreatment.total_assets/liabilities`, or `sourceTotalAssets/Liabilities`):
```javascript
const hasAuthoritativeField = isAsset
  ? (ledgerEntry.authoritativeTotalAssets !== undefined || (ledgerEntry.targetTreatment && ledgerEntry.targetTreatment.total_assets !== undefined) || ledgerEntry.sourceTotalAssets !== undefined)
  : (ledgerEntry.authoritativeTotalLiabilities !== undefined || (ledgerEntry.targetTreatment && ledgerEntry.targetTreatment.total_liabilities !== undefined) || ledgerEntry.sourceTotalLiabilities !== undefined);

if (!hasAuthoritativeField) {
  throw new Error(`MISSING_AUTHORITATIVE_FIELD: Ledger record ${ledgerEntry.manifestId || ledgerEntry.id} does not contain authoritative ${fieldKey}`);
}
```
If the authoritative property is missing or `undefined`, the verifier immediately fails closed with `MISSING_AUTHORITATIVE_FIELD`.

### 2.2 Missing-Disclosure Path (`correction.intendedValue === null`)
When `intendedValue === null`:
- Requires the targeted ledger authoritative field to equal exactly `null` (`ledgerAuthoritativeVal === null`). Any numeric value (e.g. `0` or positive) throws `LEDGER_RESTORED_VALUE_MISMATCH`.
- Requires the source profile to satisfy missing-disclosure standards: rejects source-confirmed positive values (`POSITIVE_TOTAL_MUTATION_FORBIDDEN`) and genuine zeros (`GENUINE_ZERO_COERCION_FORBIDDEN`).
- Rejects contradictory disclosure classifications: if `correction.disclosureClassification` is `'POSITIVE'` or `'VERIFIED_GENUINE_ZERO'`, throws `CONTRADICTORY_DISCLOSURE_CLASSIFICATION`.

### 2.3 Zero-Preservation Path (`correction.intendedValue === 0`)
When `intendedValue === 0`:
- Requires the targeted ledger authoritative field to exist explicitly and equal `0` (`ledgerAuthoritativeVal === 0`). Explicit `null` or non-zero throws `LEDGER_RESTORED_VALUE_MISMATCH`.
- Requires the source field to be explicitly parsed as numeric zero (`sourceVal === 0`). If the source value is `null` or undefined, throws `ZERO_FABRICATION_FORBIDDEN`.
- Rejects contradictory missing-disclosure classifications: if `correction.disclosureClassification` is `'UNDISCLOSED_OMITTED'` or `'POSITIVE'`, throws `CONTRADICTORY_DISCLOSURE_CLASSIFICATION`.

### 2.4 Consistent Contract Enforcement Across Asset and Liability Branches
The identical contract and invariant gates are enforced symmetrically on both the `ASSET` and `LIABILITY` branches. Positive restorations require positive source and ledger values; zero preservation requires source and ledger zero; missing disclosure requires source and ledger explicit null.
