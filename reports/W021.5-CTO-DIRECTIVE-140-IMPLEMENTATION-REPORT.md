## 3. P0 — Authentication Authority Repair & Test Seam Containment (Section 4)

### 3.1 Elimination of Caller-Supplied Role Claims (`apps/api/src/lib/userAuth.ts`)
- **Root Cause Remediated:** `resolveAuthenticatedUser` previously consulted `user.user_metadata?.role` as an alternative role source. Because `user_metadata` is caller-writable during signup/update, this permitted privilege escalation.
- **Architectural Fix:**
  - Removed `user.user_metadata?.role` completely from role resolution.
  - Privileged roles derive **ONLY** from server-managed `user.app_metadata?.role` or server-side authoritative role lookup.
  - Role candidate is validated against `VALID_ROLES` (`citizen`, `moderator`, `admin`, `contributor`, `volunteer`, `coordinator`).
  - Any unknown, malformed, or missing role strictly fails closed to `'citizen'`.

### 3.2 Test Seam Containment
- `setTestTokenValidator` is now strictly contained:
  ```typescript
  export function setTestTokenValidator(validator: TestTokenValidator | null): void {
    if (validator !== null) {
      if (process.env.NODE_ENV !== 'test' || process.env.TEST_HARNESS_ACTIVE !== 'true') {
        throw new Error('SECURITY VIOLATION: Test token validator can only be registered when NODE_ENV === "test" and TEST_HARNESS_ACTIVE === "true".');
      }
    }
    customTestTokenValidator = validator;
  }
  ```
- Calling `setTestTokenValidator` outside an isolated test harness (`NODE_ENV === 'test'` and `TEST_HARNESS_ACTIVE === 'true'`) throws a fatal security exception.
