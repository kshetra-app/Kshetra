## 4. Strict Eligibility Gate Hardening (§3)

`validateEligibilityGate()` in `scripts/adjudication_validators.mjs` was hardened to prevent accidental equality, truthy coercion, or invalid states:

### 4.1 Invariants Enforced:
1. **Strict Boolean Verifier Check:** `passesExistingOfflineVerifier === true` (strictly checked with `!== true`). Truthy values like `'true'`, `1`, or `{}` are strictly rejected with `VERIFIER_GATE_VIOLATION`.
2. **Financial Value Domain Enforcement:** `expectedDatabaseValue` and `proposedValue` must pass `isValidFinancialValue(v)` (`v === null || (typeof v === 'number' && Number.isSafeInteger(v) && v >= 0)`). Any `undefined`, `NaN`, string, float, or negative number is rejected with `INVALID_FINANCIAL_VALUE_DOMAIN`.
3. **Supported States:** Must be one of `['ELIGIBLE', 'INELIGIBLE', 'REQUIRES_REVIEW']`. All other values are rejected with `UNSUPPORTED_ELIGIBILITY_STATE`.
4. **`ELIGIBLE` Invariant:** Requires `passesExistingOfflineVerifier === true` and `expectedDatabaseValue !== proposedValue` (cannot be eligible if no mutation is required).
5. **`INELIGIBLE` Invariant:** Requires `expectedDatabaseValue === proposedValue` and `passesExistingOfflineVerifier === false`.
6. **`REQUIRES_REVIEW` Invariant:** Requires `passesExistingOfflineVerifier === false`, `expectedDatabaseValue !== proposedValue`, and non-empty `rejectionReason`.

### 4.2 Production Adversarial Tests (Test 15):
Test 15 exercises `validateEligibilityGate()` across 16 distinct sub-cases covering boolean `false`, `undefined`, `null`, `'true'`, `1`, unsupported states, `undefined` values, `NaN`, negative numbers, floats, strings, ineligible mismatches, ineligible with verifier `true`, requires review with verifier `true`, requires review with equal values, and valid control cases.

## 5. SQL Chunk Validation and Coverage (§4)

`validateSqlChunks()` in `scripts/adjudication_validators.mjs` was strengthened with schema validation, domain validation, and bidirectional crosswalk reconciliation:

### 5.1 Validation Rules:
1. **18-Column Schema:** Every tuple line starting with `('` must have exactly 18 tokens. Mismatches throw `MALFORMED_SQL_TUPLE`.
2. **Canonical Target UUID:** Column 1 target UUID must match `CANONICAL_UUID_REGEX`. Mismatches throw `MALFORMED_SQL_TARGET_UUID`.
3. **Financial Value Domain:** Column 12 liability token must be `NULL` or non-negative integer string `/^\d+$/` parsing to a safe integer. Mismatches throw `INVALID_SQL_FINANCIAL_VALUE`.
4. **Target Uniqueness:** Duplicate target UUIDs in SQL throw `DUPLICATE_SQL_TARGET_UUID`.
5. **Bidirectional Crosswalk Reconciliation:** With `{ assertFullCoverage: true }`, all target UUIDs in `crosswalkTargetUuidSet` must be present in parsed SQL tuples. Any missing target throws `CROSSWALK_TARGET_MISSING_IN_SQL`.
