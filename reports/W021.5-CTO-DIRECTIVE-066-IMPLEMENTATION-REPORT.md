## 2. Mandatory Ledger / Source / Correction Binding (§2)

`scripts/verify_financial_remediation.mjs` was remediated to enforce fail-closed binding across manifest, crosswalk, component ledger, and source coordinate:

### 2.1 Fail-Closed Binding on Absent Ledger Evidence (§2.1)
For every financial correction requiring source-value verification:
- Requires **exactly one** matching canonical manifest record (`affidavitId`).
- Requires **exactly one** matching crosswalk record mapping `manifestId` to target `candidateUuid`.
- Requires **exactly one** matching component-ledger record (`manifestId`).
- Proves **consistent target UUID** between crosswalk and component ledger (`CROSSWALK_LEDGER_UUID_MISMATCH`).
- Requires a valid authoritative value in the component ledger for the targeted financial field (`MISSING_AUTHORITATIVE_FIELD`).
- Requires a valid source coordinate resolving to the identical candidate identity (`candidateName`) and constituency (`acNo`).
- Enforces strict three-way agreement: `sourceValue === ledgerValue === intendedValue` (`SOURCE_RESTORED_VALUE_MISMATCH`, `LEDGER_RESTORED_VALUE_MISMATCH`).
- Requires exact agreement between the correction's declared original represented value and the manifest's current field value (`CORRECTION_ORIGINAL_VALUE_MISMATCH`).
- Fails closed with explicit error codes on missing entries, missing authoritative fields, malformed numbers, or target mismatches.

### 2.2 Row-Level Eligibility Gate (§2.2)
Before applying any change to the in-memory representation, `validateCorrectionEligibility` validates the full eligibility chain:
- **Positive Restorations:** Must be supported by the exact source profile value and matching authoritative ledger total.
- **Missing Disclosures:** Must never be inferred solely from an absent application seed property. Requires designated affirmative evidence; absent evidence fails closed with `MISSING_AFFIRMATIVE_DISCLOSURE_EVIDENCE`.
- **Genuine Zero Preservation:** Source-confirmed zero cannot be mutated to `null` (`GENUINE_ZERO_COERCION_FORBIDDEN`).
- **Positive Total Preservation:** Source-confirmed positive total can never be changed to `null` or `0` (`POSITIVE_TOTAL_MUTATION_FORBIDDEN`).
- **Zero Fabrication Forbidden:** Missing disclosure cannot be mutated to zero without affirmative proof (`ZERO_FABRICATION_FORBIDDEN`).
- **Conflict Blocking:** Any unresolved source conflict blocks the individual correction and prevents a `PASS` verdict.

### 2.3 Exact Set Membership & Five Financial Classification Groups (§2.3)

## 3. Source Parser & Path-Security Hardening (§3)

The custom lexical parser and path security in `scripts/verify_financial_remediation.mjs` were remediated to eliminate scanning traps:

1. **Same-Line Block Comment Trap (`extractObjectLiteralAtLine`):**
   - Lexical scanner scans from index `0` of the target line tracking `//` line comments, `/* ... */` block comments, string literals (`'...'`, `"..."`, `` `...` ``), and escape sequences.
   - If an opening brace `{` is inside a same-line block comment, it is rejected with `NO_ACTIVE_OPENING_BRACE_AT_COORDINATE`.
2. **Comment & String Escape Immunity:**
   - Braces, property keys, and financial-looking tokens inside comments or strings are ignored during object boundary detection and property extraction.
   - Escaped quotes (`\"`, `\'`) and backslashes do not alter object boundaries.
3. **Property Leaking & Depth Isolation:**
   - State machine tracks brace depth; nested properties do not leak into top-level financial fields.
   - Adjacent candidate objects are strictly isolated; opening and closing braces cleanly delineate candidate boundaries.
4. **Strict Identity Verification (`parseSourceProfile`):**
   - Resolves source coordinates against both `candidateName` and `acNo`.
   - Missing candidate identity or constituency number in either source or expected manifest fails closed (`MISSING_SOURCE_CANDIDATE_NAME`, `MISSING_SOURCE_AC_NO`, `MISSING_MANIFEST_CANDIDATE_NAME`, `MISSING_MANIFEST_CONSTITUENCY_NUMBER`).
5. **Duplicate Property Rejection (`commitProperty`):**
   - Detects duplicate property keys within a source object literal and throws `DUPLICATE_PROPERTY_KEY`. Silent overwriting by "last-parsed" value is completely eliminated.
6. **Strict Path Security (`safeCanonicalPath`):**
   - Validates paths against traversal (`..`), UNC paths (`\\\\`), Windows drive escapes (`C:`), URL schemes (`://`), and null bytes (`\\0`).
   - Resolves canonical realpaths within `REPO_ROOT` confinement across Windows and non-Windows execution environments.
7. **Safe Numeric Parsing:**
   - Numeric values quoted as strings (e.g. `"1000000"`) are rejected with `INVALID_NUMERIC_VALUE`. Coercion of malformed strings or unsafe integers is strictly prohibited.
