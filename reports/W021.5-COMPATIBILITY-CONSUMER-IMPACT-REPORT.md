## 1. Executive Summary

During Directive 083 and 084, the Fastify API endpoint `GET /api/v1/states/:stateCode/constituencies/:constituencyId` returned a fixed response object named `election2023`. Under Directive 084, a temporally correct contract `recentElection` and an `elections[]` historical array were introduced to accurately represent actual election years (e.g. 2025 for Delhi, 2024 for Andhra Pradesh/Maharashtra/Haryana/Odisha, 2023 for Telangana/Karnataka, 2022 for UP, etc.) and to allow nullable numeric metrics (`winnerVotes: number | null`, `margin: number | null`, `marginPercent: number | null`).

However, `election2023` was retained as an alias for backward compatibility. This report evaluates every repository consumer of `election2023`, documents the structural data-distortion risks of its non-null numeric interface, details the migration status of internal consumers, and establishes a safe deprecation timeline for external API clients.

---

## 2. The Structural Flaw of `election2023`

The original legacy contract for `election2023` was defined as:
```typescript
election2023: {
  winner: string;
  winnerName: string;
  winnerVotes: number;
  runnerUp: string;
  margin: number;
  marginPercent: number;
}
```

### Critical Semantic Failures:
1. **Temporal Falsehood:** For any constituency where the assembly election occurred in a year other than 2023 (e.g. Delhi in 2025, Andhra Pradesh in 2024, Uttar Pradesh in 2022, West Bengal in 2021, Bihar in 2020), returning results inside a key named `election2023` falsely claims that the election occurred in 2023.
2. **Forced Zero-Coercion:** Because `winnerVotes`, `margin`, and `marginPercent` were defined as non-null `number` fields, any constituency where votes were unrecorded, uncontested, or pending ingestion was forced to coerce `null` to `0` (`winnerVotes: recentElection.winnerVotes ?? 0`). In client UIs, this caused unrecorded margins to display as `"Margin: 0 votes"` rather than `"Not Reported"` or `"Uncontested"`, creating severe political misinformation.

## 4. Consumer Impact & UI Safety Verification

### Mobile Screen Audit:
- In `apps/mobile/app/constituency/[id].tsx`:
  - `effectiveWinnerVotes`: uses `apiDetail?.recentElection?.winnerVotes` (which is `number | null`). If `null`, it renders `"Not Reported"`.
  - `effectiveMargin`: uses `apiDetail?.recentElection?.margin` (which is `number | null`). If `null`, it renders `"—"`.
  - `effectiveMarginPercent`: uses `apiDetail?.recentElection?.marginPercent` (which is `number | null`). If `null`, it renders `"—"`.
  - `effectiveElectionYear`: uses `apiDetail?.recentElection?.electionYear` (which is `number | null`). If `null`, it renders `"Recent Election Result"`.
- **Verdict:** Zero internal mobile screens are affected by zero-coercion. All mobile screens have successfully migrated to `recentElection`.

### Fastify API Route Audit:
- In `apps/api/src/routes/constituencies.ts`:
  - Response object contains both `recentElection` (modern, truthful, nullable) and `election2023` (legacy alias).
  - External API consumers that have not updated their client code will continue to receive HTTP 200 with `election2023`.
  - Modern API consumers receive `recentElection` and `elections[]` with full temporal fidelity and null-preservation.

---

## 5. Fate of `election2023` & Deprecation Schedule

1. **Immediate Action (Directive 085):**
   - The alias `election2023` is marked `@deprecated` in the OpenAPI/Fastify schema and source code.
   - All internal mobile screens are verified to be 100% decoupled from `election2023`.
2. **Phase 1 (Milestone W022):**
   - Emit an HTTP `Deprecation: true` and `Sunset: Wed, 01 Jul 2027 00:00:00 GMT` header on responses that request or consume legacy fields.
3. **Phase 2 (Milestone W023 — Breaking API Cutover):**
   - Remove `election2023` from `getConstituencyDetailSchema` response definition and Fastify serialization payload.
   - Require all external consumers to use `recentElection` and `elections[]`.

---

## 6. Conclusion & Governance Statement

No breaking API change has been introduced in Directive 085. Existing mobile clients and legacy automated tests continue to operate with 100% backward compatibility, while all active user interfaces consume truthful, temporally accurate, non-coerced political data.
