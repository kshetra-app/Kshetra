## 4. Workstream 4 — Schema Invariants, Column Mechanics & Identity Protection

### 4.1 PostgreSQL Mechanics for `total_assets` (Generated Column)
- **Schema DDL (`008_election_affidavits.sql`):**
  ```sql
  total_assets BIGINT GENERATED ALWAYS AS (
    self_movable_assets + self_immovable_assets + spouse_movable_assets + spouse_immovable_assets
  ) STORED,
  total_liabilities BIGINT DEFAULT 0,
  ```
- **Constraint Enforcement:** In PostgreSQL, executing an explicit update on a generated column (e.g., `UPDATE candidate_affidavits SET total_assets = NULL`) raises PostgreSQL error `42601: cannot insert into or update column "total_assets"`.
- **Architectural Solution (Zero DDL):** Because the expression has no `COALESCE`, setting the 4 component columns to `NULL` causes the stored generated expression (`NULL + NULL + NULL + NULL`) to compute `NULL` natively:
  ```sql
  UPDATE public.candidate_affidavits
  SET self_movable_assets = NULL,
      self_immovable_assets = NULL,
      spouse_movable_assets = NULL,
      spouse_immovable_assets = NULL
  WHERE id = <target_affidavit_id>;
  ```
- **Total Liabilities Mechanics:** `total_liabilities` is a regular nullable column with `DEFAULT 0`. It can be updated directly via `SET total_liabilities = NULL WHERE id = <target_affidavit_id>;`.
