## 1. Executive Adjudication and Current Political Reality

Directive 018 addresses a critical temporal correctness defect: general elections previously treated as future 2026 simulations have, as of October 2026, occurred in five major Indian jurisdictions:
1. **Tamil Nadu (TN)** — 234 assembly constituencies
2. **Kerala (KL)** — 140 assembly constituencies
3. **West Bengal (WB)** — 294 assembly constituencies
4. **Assam (AS)** — 126 assembly constituencies
5. **Puducherry (PY)** — 30 assembly constituencies (+ 3 nominated)

### 1.1 Ground Truth Adjudication: Speculative Simulations vs Official Returns
A thorough forensic audit of the repository seed files and generation scripts establishes the following:
- **Tamil Nadu, Kerala, West Bengal:** The seed fields (`winner2026`, `winnerName2026`, `winnerVotes2026`, `margin2026`) are **100% speculative pre-election simulations** generated prior to the elections (e.g. TVK projected winning 99 seats with actor Vijay in Perambur). No official Election Commission of India (ECI) Form 20 (Final Result Sheet) or Form 21E (Declaration of Result) primary returns exist in the repository for 2026.
- **Assam:** The `winner2026` fields in `data/seed/assam-constituencies.ts` were identified as mislabeled genuine 2021 election returns rather than actual 2026 results.
- **Puducherry:** The seed file generated by `scripts/build-py-2026.mjs` contains a partial, unverified scrape with missing votes (0 votes recorded in ACs such as Thirubhuvanai).

### 1.2 Systemic Temporal Invariant Contract
Rather than silently misrepresenting the expired 2021 legislative tenure as the active current term, or allowing speculative pre-election simulations to leak into official officeholder queries, a strict temporal contract has been implemented:
1. **Segregation:** Speculative projections remain strictly segregated under the optional `projection?: SimulationProjection` contract with the explicit disclaimer: *"Simulated Projection — Not an Official Result"*.
2. **Explicit Stale State:** Constituencies in the five expired 2021 jurisdictions expose explicit metadata:
   - `dataStatus: 'STALE_PENDING_INGESTION'`
   - `isStale: true`
   - `termStatus: '2021_TERM_EXPIRED_PENDING_2026_PRIMARY_INGESTION'`
   - `electionYear: 2021` (identifying the baseline data year truthfully)
3. **Delhi General Election Baseline:** The repository previously defaulted Delhi to 2022 (the Municipal Corporation of Delhi local body election). This defect has been resolved in both API (`genericToBrief`) and Mobile (`genericAdapter` / `genericBriefAdapter`) to resolve the **February 2025 Legislative Assembly General Election** (e.g., AC 1: Raj Karan Khatri, BJP).
4. **Karnataka Delimitation Alignment:** Statutory Delimitation 2008 / Migration 059 reconciliation establishes the ground truth for all 224 Karnataka assembly constituencies, documenting 30 exact matches, 180 shifted names, and 14 duplicate phantom seats across 7 seat pairs.
5. **Generator Ingestion Hardening:** Identified that in-memory AST patch arrays (specifically `ENRICHED_PROFILES` in `karnataka-mla-profiles.ts`) caused duplicate affidavit collisions (`DQ-W021.5-B2.2E-001`). Implemented candidacy natural-key deduplication and conflict detection.

### 3.1 Delhi Root Cause & Remediation
- **The Defect:** In `apps/api/src/services/stateData.ts`, the generic mapping function `genericToBrief` evaluated:
  ```typescript
  currentParty: c.winner2024 ?? c.winner2023 ?? c.winner2022 ?? c.winner2021 ?? c.winner ?? '',
  currentMLA: c.winnerName2024 ?? c.winnerName2023 ?? c.winnerName2022 ?? c.winnerName2021 ?? c.winnerName ?? '',
  ```
  This omitted `c.winner2025` entirely, causing Delhi assembly records to fall through to `winner2022`. In addition, `apps/mobile/lib/stateDataAdapter.ts` hardcoded `genericAdapter(c, 'DL', 2022)` and `genericBriefAdapter(c, 'DL', 2022)`.
- **Constitutional Reality:** Delhi Legislative Assembly general elections occurred in February 2020 and February 2025. In 2022, Delhi held municipal elections for the Municipal Corporation of Delhi (MCD — 250 wards), which are civic local body elections, not Legislative Assembly MLA contests.
- **Remediation Executed:**
  1. Updated `apps/api/src/services/stateData.ts` to evaluate `c.winner2025 ?? c.winner2024 ...`.
  2. Updated `apps/mobile/lib/stateDataAdapter.ts` lines 336 and 518 to pass `2025`.
  3. API and mobile now resolve the February 2025 general election results accurately (e.g., AC 1 Narela: Raj Karan Khatri, BJP).

## 5. Generator Hardening & Source Semantics Audit

### 5.1 Root Cause of Duplicate Candidacy Collision (`DQ-W021.5-B2.2E-001`)
A forensic audit of `scripts/generate-b2-2e-forensic-manifests.mjs` and the source seed files revealed the architectural root cause of `DQ-W021.5-B2.2E-001`:
1. In `data/seed/karnataka-mla-profiles.ts`, lines 3949–3968 contain:
   ```typescript
   const ENRICHED_PROFILES: (Partial<MLAProfile> & { acNo: number })[] = [
     { acNo: 38, name: 'Siddaramaiah', party: 'INC', gender: 'M', terms: 5, age: 76, education: 'LLB', profession: 'Advocate' },
     { acNo: 31, name: 'Basavaraj Bommai', party: 'BJP', gender: 'M', terms: 4, age: 63, education: 'BE', profession: 'Engineer / Politician' },
     ...
   ];
   ```
   This is an **in-memory monkey-patch array** executed at file evaluation time to enrich profile records.
2. The naive AST regular expression extractor in `generate-b2-2e-forensic-manifests.mjs` scanned all object literals in the file indiscriminately, treating line 3951 as if it were an independent candidate affidavit.
3. Because the B2.2-D candidacy manifest also mapped line 3951, the generator produced **two affidavit records for the same candidacy** (`candId: 0215b22d-can-00000031`).
4. Basavaraj Bommai filed exactly **one official ECI Form 26 affidavit** for Shiggaon (AC 31) in the 2023 Karnataka General Election. Line 3951 is not a second filing.

### 5.2 Generator Hardening & Ingestion Deduplication
The manifest generator has been hardened with:
- Natural-key tracking via `affidavitByCandidacy` map (`Map<candidacyId, AffidavitRecord>`).
- Conflict detection logging: If a duplicate occurrence contains conflicting non-null financial values (`total_assets` or `total_liabilities`), an explicit warning (`[INGESTION_CONFLICT]`) is emitted.
- Safe attribute merging: Auxiliary fields (`education`, `profession`) are merged without clobbering non-null financials.
- Missing disclosures are strictly preserved as `null` and never converted to zeros.
- **Invariant Hold:** The defect `DQ-W021.5-B2.2E-001` remains **OPEN** pending formal CTO review and frozen manifest authorization.
