## 3. Definitive Resolution of Defect DQ-W021.5-B2.2E-001

### 3.1 Defect Background & Forensic Root Cause
Legacy schema migration `008_candidate_affidavits.sql` declared asset and liability columns with `DEFAULT 0`. When candidates did not file Form 26 affidavits, or when disclosure records were missing or withheld, API serialization and mobile client formatters rendered these candidates as possessing ₹0 assets. In political reality, an unfiled disclosure is unknown/missing, not a declaration of zero net worth. Converting unknown financial data to ₹0 violates the foundational data-truth invariant.

### 3.2 Authoritative 6-Rule Schema Standard (DEC-134)
To resolve this defect definitively, the following 6-rule standard has been formulated, documented in `DEC-134`, added to Section 11 of `DEFECT_REGISTER.md`, and verified via 105 automated unit and integration tests:

1. **Strict Nullability:** Asset and liability columns must be defined as nullable (`BIGINT NULL CHECK (val >= 0)`). `DEFAULT 0` is strictly forbidden.
2. **Disaggregation of Asset Classes:** Movable and immovable assets must be tracked in distinct, unaggregated columns (`movable_assets`, `immovable_assets`).
3. **ECI Form 26 Entity Separation:** Sworn disclosures must separately record candidate, spouse, and dependent assets (`candidate_assets`, `spouse_assets`, `dependent_assets`). Cross-entity averaging or blanket aggregation is prohibited.
4. **Distinct Gross vs Net Liabilities:** Gross liabilities (`total_liabilities`) must be tracked separately from gross assets. Null values in liabilities must not collapse to zero when computing financial summaries.
5. **Fail-Closed Client & API Serialization:** When an affidavit is unfiled, formatters must render explicit null representations:
   $$\text{formatINR}(\text{null}) \implies \text{'Not Disclosed'} \quad (\text{NEVER } \text{'₹0'})$$
6. **Canonical Migration 068 DDL Specification:** Schema remediation is specified in Migration 068 DDL, deprecating Migration 008 defaults and introducing strict check constraints.

### 3.3 Executable Verification
The 6-rule standard was verified across 105 test assertions in `tests/financial_remediation.test.mjs` (105/105 passed cleanly):
- Disaggregation checks (movable vs immovable).
- Entity checks (candidate vs spouse vs dependent).
- Null preservation checks (`null !== 0`).
- Formatting boundary checks (`formatINR(null) === 'Not Disclosed'`).
- DDL constraint validation.
