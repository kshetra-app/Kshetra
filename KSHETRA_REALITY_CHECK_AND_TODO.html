1. Bottom Line (TL;DR)

KSHETRA is a genuinely large and technically solid offline mobile prototype. The code compiles with zero TypeScript errors across all three packages (mobile, API, shared), the documentation is unusually disciplined (a 4,399-line build log covering 51 sprints), and the data layer is enormous (197 seed files, 23 DB migrations, 22 states with map polygons).
However, the project is further from "production / gold standard" than the celebratory docs suggest. Three realities stand out:
  • The whole backend is built but not switched on. Supabase, the Fastify API, AI, push notifications and KYC all exist in code, but the app ships with empty Supabase/AI/EAS keys and runs entirely offline on bundled seed data. Social/feed/civic actions write to local device storage, not a real shared backend.
  • Data depth is very uneven. Only ~3–4 states are truly "gold". Most states have short constituency seeds (fewer than official seat counts) and 9 states have empty placeholder maps.
  • The newest feature (Sprint 51 Administrative Hierarchy) is data/backend-only — it has no UI in the app yet.

2. What KSHETRA Is Meant To Be

Per README.md and KSHETRA_360_Analysis.md, the vision is to be India's political operating system for the post-delimitation era, with three product engines:

EnginePurposeBusiness modelCurrent state
Constituency IntelligenceInteractive maps, boundaries, demographics, election historyFree civic layerLargely built (offline)
Media & Journalist NetworkGeo-tagged news, journalist verification, embeddable widgetsFreemiumIn-app screens built; web widgets & backend missing
Campaign ManagerContent distribution, voter segmentation, field ops, analyticsPaid SaaSIn-app screens + store built; not live/monetized

Plus cross-cutting bets: a Delimitation Simulator (the core strategic moat), an AI analysis layer, multilingual support, and a content-accountability / trust-and-safety framework for legal compliance.

Tech stack (as documented & confirmed in repo): React Native + Expo (TypeScript), MapLibre maps, Zustand state, Fastify API, Supabase (PostgreSQL + PostGIS + pgvector), Turborepo monorepo, Jest tests.

*J&K was rebuilt to gold in a later session per the audit log, but the summary table predates that fix — itself a sign the trackers are not perfectly in sync.

Key nuance the marketing docs blur: "31 states wired" is true at the plumbing level (every state appears in dispatchers and registries), but most states' seed data is short of official seat counts (e.g. Rajasthan 187/200, MP 208/230, Bihar 227/243, UP 401/403) and 9 states have no real map geometry at all. "Wired" ≠ "complete & accurate".

6. Depth vs. The "Gold Standard"

The Telangana dataset defines the gold bar: 119 constituencies with 2014/2018/2023 results, full MLA profiles, full demographics, a double-entry political ledger, and a trivia engine, all test-covered. Measuring other states against it:

Data dimensionGold depthReality across 31 states
Constituencies w/ real resultsFull, sourcedUneven — ~8 strong, many "short" seeds, some auto-generated/stub.
DemographicsPer-AC, sourcedKA & MH still partial stubs; several states are indicative estimates.
Historical results (multi-cycle)2 prior cycles per AC"Minimal / needs verification" for KL, WB, UP, TN per parity tracker.
Political timeline / triviaRich, audited ledgerMany states are "stub" auto-generated entries.
MLA profiles (assets/cases/edu)Full MyNeta/ADR fields8 states deeply scraped; others identity-level only (no fabricated fields — good integrity).
Rajya Sabha MPs—142/245 (58%), 103 remaining.
Credit where due: The team's data-integrity discipline is excellent — where real data is unavailable, fields are omitted rather than fabricated, and estimates are explicitly labelled. That honesty is a real asset for a political-data product.

8. How The Scope Evolved (initial → added later)

Initial scope (Milestones 1–23, v0.1.0)

  • Telangana-first interactive map + 119 profiles
  • Find My Constituency (GPS)
  • Intelligence dashboard, search, analytics API
  • Offline persistence (MMKV + Zustand)
  • Historical data, MLA profiles, demographics
  • Supabase + Auth, EAS build, CI/CD
  • Multi-state architecture, AI integration, i18n
  • Trivia engine + political ledger

Added during development (Sprints 12–51)

  • Civic engagement pipeline, issues, sentiment, report cards
  • Election affidavits & candidate transparency
  • Promise tracker, Aspiring Leaders, Leadership Academy
  • Delimitation engine + interactive simulator
  • Unified Legislator Profile (merged Candidate X-Ray)
  • Content Creator Accountability + Content Promotion Pipeline
  • Journalist platform, Politician portal, Campaign Manager
  • Parliament data (LS/RS), 31-state expansion, full i18n
  • Political Shorts, live-election ticker, broadcast API
  • Map overhaul (MapLibre, gestures, multilingual labels)
  • Administrative Hierarchy framework (Sprint 51)

The pattern: the product grew from a focused Telangana map into a very broad multi-engine platform. Breadth expanded faster than depth/backend hardening — which is exactly where the current gaps sit.

10. Risks & Watch-outs

  • "Demo-ready" mistaken for "production-ready". The offline app is great for investor demos, but go-to-market claims (SaaS, media licensing) require the P1 backend work first.
  • Data accuracy is a legal/credibility risk for a political product. Short seeds and estimated demographics must be clearly labelled until corrected.
  • Single-developer build fragility — the Windows path / Hermes manual steps suggest releases aren't yet automated or reproducible by others.
  • Doc drift — decisions made off the optimistic 360° doc could misallocate effort; trust the audit doc + code over the marketing docs.
  • Compliance features are scaffolding, not enforcement — CCA/RPA silence windows exist in code but depend on the un-implemented KYC + live backend to actually function.
